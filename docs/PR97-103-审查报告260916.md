### ⚠️ 问题

**P2 · `attach_extended_fields` 的短路只检查第一行**

```python
if all(col in rows[0] for col in want):
    return rows
```

`rows[0]` 有列就认为整批都有。若出现**行间不一致**（多段拼接、或 DAO 版本混用），后续行会**漏补**。
风险实际不高（同一次 DAO 查询列必然一致），但**代码没有写明这个前提**，读代码的人会以为它做了逐行检查。

建议二选一：
- 改为逐行判断：`if all(all(col in r for col in want) for r in rows): return rows`
- 或保留现状但补一句注释说明"同一次查询列一致，故抽查首行"

**这个问题之所以没被测试暴露**：`test_notice_dao_extended.py` 的 `FakeDAO` **只返回 1 行**，
所有用例都是单行 ⇒ 「只查首行」的假设从未被压到。

**P3 · PEP8 / 可读性**：`page_notices_rows` 定义在**调用它的 `public_notice_page` 之后**，
且函数前只有 1 个空行（PEP8 要求模块级函数间 2 个空行）。功能正常（Python 运行时解析名字），
但建议上移到调用者之前并补空行。

**P3 · `test_notice_extend_contract.py` 的 `pytest.skip`**：`items` 为空时跳过。
若 CI 的 `campus_notice` 恒为空，该用例覆盖为零。可接受，但需知悉。
