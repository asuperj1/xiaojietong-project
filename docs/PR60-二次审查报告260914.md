## 2. ❌ P1 未修 + 引入 500 回归（阻断）

### 事实

调用方已改为传 `dry_run=`：

```python
# routers/admin.py
result = knowledge.purge_by_source_prefix(
    body.source_prefix, purge_vectors=body.purge_vectors, dry_run=body.dry_run)   # ← dry_run
except ValueError as exc:            # ← 只接 ValueError
    raise err_param(str(exc)) from exc

# cli/kb_import.py 同理，并读取 result['pattern'] / result['doc_ids']
```

但 **`backend/app/services/knowledge.py` 本 PR 一个字都没改**：

```python
def purge_by_source_prefix(prefix: str, *, purge_vectors: bool = True) -> dict:   # ← 没有 dry_run
    p = normalize_source(prefix)
    rows = cpp_bridge.query(
        "SELECT id FROM knowledge_doc WHERE source_url LIKE ? AND status != 2", [f"{p}%"])  # ← % 仍未转义
```

⇒ **`TypeError: unexpected keyword argument 'dry_run'`**，而调用方只 `except ValueError`
⇒ **`POST /admin/knowledge/purge` 与 CLI `--purge-source-prefix` 都会 500**。

### 同时，P1 的**原始危险仍然存在**

- `%` / `_` **仍未转义** ⇒ 传 `source_prefix="%"` 依然 `LIKE '%%'` **清空全库**；
- 无最小长度、无强制 `dry_run` 默认、无确认；
- 测试里引用的 `MIN_PURGE_PREFIX_CHARS` / `like_prefix_pattern` / `result['pattern']`
  **在仓库里完全不存在**（`git grep` 只命中测试文件自身）。

### 实测（作者自己新加的 3 个用例，全部失败）

```
FAILED tests/test_kb_import.py::test_like_prefix_escapes_wildcards
    ImportError: cannot import name 'MIN_PURGE_PREFIX_CHARS' from 'app.services.knowledge'
FAILED tests/test_kb_import.py::test_purge_prefix_guard_rejects_short_prefix
    Failed: DID NOT RAISE ValueError           # "" / "/" / "%" / "a" / "ab" 全部放行
FAILED tests/test_kb_import.py::test_purge_matches_literally_not_as_wildcard
    TypeError: purge_by_source_prefix() got an unexpected keyword argument 'dry_run'
```

> ⚠️ **三条测试恰好把三个缺口各证了一遍** —— 转义没做（ImportError）、
> 短前缀没拦（DID NOT RAISE）、`dry_run` 没实现（TypeError）。
> ⇒ **描述里的自测数字不可信，且 CI 必红**。

### 建议修法（照现有测试的预期实现即可）

在 `services/knowledge.py` 落地三件事，调用方就无需再改：
1. `MIN_PURGE_PREFIX_CHARS = 3`，`len(p) < MIN` → `raise ValueError`；
2. `like_prefix_pattern(p)`：转义 `\` `%` `_` 后再拼 `%`（或用 `LOCATE(?, source_url) = 1`）；
3. `purge_by_source_prefix(prefix, *, purge_vectors=True, dry_run=False)`，
   返回体加 `pattern`；`dry_run=True` 只返回 `matched`/`doc_ids` 不删除。
