## 三、🔴 缺陷

### 缺陷 1（P1）· `prelabel` 产出的样本**通不过自己的校验**

`prelabel.py::prelabel_samples` 的"只填空位"判断把 `None` 当空位：

```python
if merged.get(k) in (None, "", [], {}):
    merged[k] = v
```

而 `KeywordTagger` 刻意返回 `{"importance": None, "category": None}`（"打分归 C28、分类归人工"），于是这两个键**被写进 labels**。

**实测证据**：
```
prelabel 后 labels = {'entities': [...], 'importance': None, 'category': None}
validate_sample -> ['labels.importance 必须是 1~5 的整数，当前 None']
>>> 预标注产物违反自己的校验
```

**为什么没被发现**：`validate_sample` 只在 `cli.cmd_collect` 里调用（校验 `raw` 样本，labels 为空必然通过），
`prelabel` / `export` 之后**都不再校验**。

**修法**（与 `export._non_empty` 统一口径 —— 该函数注释本来就写着"避免模型学会输出空字段"）：
```python
for k, v in produced.items():
    if v in (None, "", [], {}):
        continue                      # 空值不落键：避免污染校验与训练目标
    if merged.get(k) in (None, "", [], {}):
        merged[k] = v
```

### 缺陷 2（P1）· `make_sample` 的 id **跨进程不稳定**

```python
sid = sample_id or f"{source_type}-{ref or abs(hash(text)) % (10 ** 10)}"
```

Python 对 `str` 的 `hash()` 默认**随机化**（`PYTHONHASHSEED`），同一文本在不同进程得到不同 id。

**实测证据**（同一脚本连跑两次，未传 `ref`/`sample_id`）：
```
第一次: file-9439696639
第二次: file-1418800590
```

**为什么算 P1**：`C32` 的标注一致性是**按 `id` 配对**的（`pair_by_id`）。
id 不稳定 ⇒ 两个人的标注**配不上对** ⇒ Kappa 统计失效。
目前两个采集函数都会传 `ref`，所以**当前调用路径不触发**；但这是公开 API 的默认行为，一旦有人按文档省略 `ref` 就会踩到。

**修法**：用 sha256 前缀（与 `collect._text_hash` 同族，跨进程稳定）
```python
sid = sample_id or f"{source_type}-{ref or hashlib.sha256(text.encode('utf-8')).hexdigest()[:12]}"
```

### 缺陷 3（P1）· `entities[].norm: null` **进入了训练目标**

`export.py::_non_empty` 只过滤**顶层**的 None：

```python
{k: labels[k] for k in TARGET_KEYS if k in labels and labels[k] not in (None, "", [], {})}
```

`entities` 是非空 list ⇒ 整体保留，但**其中的 `norm: None` 没有清理**。

**实测证据**（真实流水线产出的 `train_extract.jsonl` 首行）：
```json
"content": "{\"entities\": [{\"type\": \"place\", \"text\": \"图书馆\", \"norm\": null}, ...
```

⇒ 这直接**教模型输出 `"norm": null`**，与 `build_messages` 自己的注释「避免模型学会输出空字段」**自相矛盾**。

**修法**：加一个实体清理函数并在 `_non_empty` 里调用
```python
def _clean_entities(ents):
    out = []
    for e in ents or []:
        if not isinstance(e, dict) or not e.get("type") or not e.get("text"):
            continue
        item = {"type": e["type"], "text": e["text"]}
        if e.get("norm") not in (None, ""):
            item["norm"] = e["norm"]      # 有归一化值才落键
        out.append(item)
    return out
```

## 四、🧪 缺陷 5（P1）· 测试覆盖盲区：15 个测试**恰好全部绕过**这三个缺陷

这是本 PR 最值得注意的地方 —— 不是"测得少"，而是**选材恰好避开了触发条件**：

| 测试 | 逃逸原因 |
|---|---|
| `test_prelabel_fills_only_empty_slots` | 用 **`NullLabeler()`**（返回 `{}`）而非会写 None 的 `KeywordTagger()` ⇒ 「只填空位」逻辑**在最危险的输入下从未被测** |
| `test_build_messages_shape_and_drops_empty_fields` | 传 **`entities: []`**（空列表）而非 `[{"type":"place","text":"图书馆","norm":None}]` ⇒ 嵌套 None 的路径没走到 |
| `test_keyword_tagger_marks_candidates` | 只断言 `entities` 的类型集合与 `norm is None`，**没断言 `labels` 的键集合** ⇒ 缺陷 1 在它眼皮底下逃逸 |
| `test_valid_sample_has_no_problems` | 只测 `make_sample` 的产物，**不跑 prelabel** ⇒ 缺陷 1 不在路径上 |
| `test_prelabel_must_not_override_human_work` | 断言 `out.labels == {...}` 精确相等 ✓ 但它测的是"跳过"分支，不覆盖"填空位"分支 |
