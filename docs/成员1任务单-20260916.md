## 5. 已验证过的坑（别再踩）

1. **同步 `throw` 写在 `return new Promise(...)` 之前 → `.catch()` 完全接不到**。
   页面里写不写 `.catch` 都一样，异常会逃逸到调用栈（`sseRequest` 的 `onError` 同理）。
   `request.js` 已修（`T-03`），**别再写回去**。
2. **`wx.getAppBaseInfo()` 的返回值里没有 `system`**（官方字段只有 SDKVersion/enableDebug/host/language/version/…）
   → 要取机型/系统请用 **`wx.getDeviceInfo()`** 或 `wx.getSystemInfoSync()`。踩过的后果是「升级基础库即退化、不报错」。
3. **`new Date('2026-09-16 10:00:00')` 在 iOS 上是 `Invalid Date`** → 用**字符串截断**（现有 `utils/format.js` 的 `formatTime` 就是这个做法）或把 `-` 换成 `/`。
4. **WXSS 不能用 `:root`**（要用 `page`）；**`.class` 工具类默认进不去自定义组件**（`styleIsolation`），要靠 `page` 标签选择器继承 CSS 变量。
5. **分类 tab 必须用 `e.currentTarget.dataset.index`**（**不是** `e.detail.value`）—— 一阶段 `FRONT-02` 就是这个坑。
6. **`@supports` 不在 WXSS 官方列举语法内**（官方只列 `@import` / 媒体查询）→ 玻璃降级方案**必须真机抽测**。
7. **`miniprogram/config/env.js` 的 `RELEASE_BASE_URL` 留空 = release 下直接抛错**（fail fast，**不会**回退本机地址）。真机联调请在开发者工具写 storage `xjt_api_base_url`。
8. **微信 `envVersion` 容易记反**：**预览 / 真机调试 = `develop`**；体验版 = `trial`；正式版 = `release`。
9. **`.catch()` 会制造虚假安全感** —— 审查任何「Promise 化」的 API 时，先看**求值阶段是否会抛**。

## 6. 提交与 PR 规矩（本仓库实测）

- `dev` **与** `main` **都受保护** → 必须走 PR，**至少 1 个批准**，且**作者不能批自己的**（本项目 PR 都是 `asuperj1` 开的 ⇒ **必须请 `yl-love` 点 `Approve`**；只点 `Comment` **不计入**批准数）。
- **批准在两种情况下会失效**：① 往 head 分支**再 push**；② **`dev` 前移（merge-base 变更）**。
  ⇒ 正确顺序：**先把分支对齐 `dev` 并冻结 → 再请队友 Approve → 立刻合并**。
- **合并方式只有 `Merge` 与 `Squash`**（没有 Rebase）。
- **建 PR 用三段式**：`https://github.com/asuperj1/xiaojietong-project/compare/dev...<你的分支>?expand=1`
- **一个页面 / 一个任务 = 一个分支 + 一个 PR**。
- ✅ **`dev` 不受限**，但**推之前先 `git fetch`**；合完记得把本地 `dev` 同步（`git switch dev && git merge --ff-only github/dev`）。
