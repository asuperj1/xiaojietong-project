### `resign()` 实现质量评估（逐规则核对）

```python
def resign(url: str, ttl_seconds: int | None = None) -> str:
    if not url or not settings.upload_signed_url_enabled:
        return url                              # ← 空值 / 关闭校验 → 原样返回 ✓
    path = str(url).split("?")[0]               # ← 先剥离旧 query，避免签名参数叠加 ✓
    if not path.startswith(f"{_URL_PREFIX}/"):  # ← 非上传路径（外链）→ 原样返回 ✓
        return url
    return signed_url(path, ttl_seconds)        # ← 对完整路径签名，不重复拼前缀 ✓
```

| 规则 | 是否覆盖 | 说明 |
|---|---|---|
| 空值 | ✅ | 避免 `None` 崩 |
| 开关关闭 | ✅ | 兼容 `XJT_UPLOAD_SIGNED_URL_ENABLED=false` |
| 外链 / 第三方 URL | ✅ | 不会被误改 |
| 旧签名剥离 | ✅ | **关键**，否则 `?e=&s=` 叠加导致校验失败 |
| 前缀重复拼接 | ✅ | 注释明确避开了 `url_for` 的坑 |

> ⚠️ 上一轮的实证背景：测试时曾发现 `GET /secondhand/items` 返回的 `images` 是**裸路径** → 开启签名校验后前端必然 403。现已修复。

## 三、⚠️ 本轮新发现：`auth.py` 漏了（建议合并前补 1 行）

`auth.py` **自己维护了一份 `_user_view()`**（与 `user.py:_view()` 重复实现），本次只修了后者：

```python
# backend/app/routers/auth.py
def _user_view(u: dict) -> dict:
    return {
        ...
        "avatar": u.get("avatar", ""),      # ← 第 43 行：仍未 resign
        ...
    }

# 登录 / 刷新都返回它
"user": _user_view(user),
```

**影响**：`POST /auth/wechat-login` 与 `POST /auth/refresh` 返回的 `user.avatar` 是**裸路径**。若前端把登录响应的头像直接渲染（或写入本地缓存），开启签名校验后会 **403 破图**；而 `GET /user/me` 返回的是已签名地址 → **同一用户两处头像表现不一致**，属易漏、易复现的边界问题。

**建议**（二选一）：

1. 最小改法：`auth.py` 也 `from app.services.storage import resign`，把第 43 行改为 `resign(u.get("avatar", ""))`；
2. 更优改法：**删掉 `auth.py:_user_view`，改为复用 `user.py:_view`** —— 消除重复实现，从根上避免"改一处漏一处"（本次就漏了）。
