# 微调模型分发与部署说明（xjt-3b）

> 归属：成员3（C++ 数据层 / 模型微调 / 数据库）· C5 产出
> 目标：让每位队友都能在本机跑起校园领域微调模型 `xjt-3b`，供后端 `chat/send` 使用。

---

## 0. 角色约定（重要，避免"互相等文件"）

| 角色 | 谁 | 职责 |
|---|---|---|
| **分发方（持有者）** | 成员3 | 本机已产出 GGUF（`E:\models\xjt-3b-f16.gguf`），负责上传团队网盘并提供分享链接 |
| **接收方** | 其他成员 | 从网盘下载 GGUF → 一键部署到本机 Ollama → 后端指向 `xjt-3b` |

**为什么不能直接给文件？** GGUF 为 5.75 GiB、LoRA 适配器 833MB，远超 Git 单文件限制，因此：
- **代码/脚本**走 Git（`ai/finetune/`）
- **模型权重**走团队网盘（夸克）/ GitHub Release

## 2. 分发方操作（成员3 · 上传夸克网盘）

> 夸克网盘，会员账号，建议用**客户端**上传（网页端大文件易中断）。

1. 打开夸克网盘客户端 → 新建目录 `校捷通/xjt-3b/`
2. 上传以下两个文件：
   - `E:\models\xjt-3b-f16.gguf`（5.75 GiB，主分发物）
   - `D:\xiaojietongproject\xiaojietong-project\ai\finetune\out\qwen3b-lora\`（可选，833MB，给有 GPU 的队友自行合并）
3. 右键 → **分享** → 有效期选 **永久有效** → 生成链接与提取码
4. 把「链接 + 提取码 + 上方 SHA256」一起发到团队群，并**在本文件第 7 节登记**，方便后续查阅
5. 同时把 `xjt-3b-f16.gguf` 传到 **GitHub Release**（见第 6 节，作为备用下载通道）

## 3. 接收方操作（队友 · 下载并部署）

### 3.1 前置条件

- 已安装 [Ollama](https://ollama.com/download)（任意较新版本）
- **磁盘剩余空间 ≥ 15 GB**（GGUF 5.75 GiB + Ollama 复制一份约 6.2 GB）

### 3.2 一键部署（推荐）

```powershell
# Windows（在仓库根目录执行）
powershell -ExecutionPolicy Bypass -File ai/finetune/deploy_ollama.ps1 -GgufPath E:\models\xjt-3b-f16.gguf
```

```bash
# Linux / macOS
bash ai/finetune/deploy_ollama.sh ~/models/xjt-3b-f16.gguf
```

脚本会自动完成：**路径检查 → SHA256 校验 → 生成适配本机路径的 Modelfile → `ollama create` → 列出模型**。

### 3.3 手动部署（脚本不可用时）

```bash
# 1) 修改 ai/finetune/Modelfile 里的 FROM 为本机实际路径
FROM /your/path/xjt-3b-f16.gguf

# 2) 创建模型
ollama create xjt-3b -f ai/finetune/Modelfile

# 3) 验证
ollama run xjt-3b "图书馆几点关门？"
```

### 3.4 让后端用上微调模型

后端配置项为 `XJT_OLLAMA_MODEL`（`backend/app/core/config.py` 中 `ollama_model`，默认已改为 `xjt-3b`）。

在 `backend/.env` 中：

```dotenv
XJT_OLLAMA_MODEL=xjt-3b
XJT_OLLAMA_BASE_URL=http://127.0.0.1:11434
```

重启后端后，`POST /api/v1/chat/send` 即走真实微调模型（Ollama 未就绪时会优雅降级为占位回复，不阻塞开发）。

## 5. 常见问题（FAQ）

| 现象 | 原因 | 解决 |
|---|---|---|
| `only one usage of each socket address` | 已有 Ollama 服务在跑（正常现象） | 无需处理；确认 `http://127.0.0.1:11434` 可访问即可 |
| `not enough space on disk` | Ollama 默认模型目录在 C 盘 | 设置环境变量 `OLLAMA_MODELS=E:\ollama\models`（指向空间充足的盘）后重启 Ollama |
| `ollama create` 报 GGUF 解析失败 | GGUF 下载损坏 | 重新下载并核对 SHA256 |
| 回答跑题 / 答非所问 | 3B 小模型 + 采样温度偏高 | 使用仓库内新版 `Modelfile`（`temperature 0.4` + `top_p 0.9` + `repeat_penalty 1.1`）重建模型 |
| 后端仍返回占位文案 | 模型名不匹配或服务未启动 | 确认 `ollama list` 有 `xjt-3b`，且 `XJT_OLLAMA_MODEL=xjt-3b` |
