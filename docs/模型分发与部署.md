# 微调模型分发与部署说明（xjt-3b）

> 归属：成员3（C++ 数据层 / 模型微调 / 数据库）· C5 产出
> 目标：让每位队友都能在本机跑起校园领域微调模型 `xjt-3b`，供后端 `chat/send` 使用。

---

## 0. 角色约定（重要，避免"互相等文件"）

| 角色 | 谁 | 职责 |
|---|---|---|
| **分发方（持有者）** | 成员3 | 本机已产出 GGUF（`E:\models\xjt-3b-f16.gguf`），负责上传团队网盘并提供分享链接 |
| **接收方** | 其他成员 | 从网盘下载 GGUF → 一键部署到本机 Ollama → 后端指向 `xjt-3b` |

**为什么不能直接给文件？** GGUF 为 5.75 GiB、LoRA 适配器 833MB，远超 Git 单文件限制，因此：
- **代码/脚本**走 Git（`ai/finetune/`）
- **模型权重**走团队网盘（夸克）/ GitHub Release

## 2. 分发方操作（成员3 · 把模型送到队友机器上）

> **关键认知：队友真正需要的是"模型"，不是"GGUF 文件"。**
> 所以不必死磕"传文件"，先按队友所在网络选路径。

### 2.0 传输方案选择（先看这张表）

| 方案 | 适用场景 | 6 GB 耗时 | 队友侧要做的事 | 推荐度 |
|---|---|---|---|---|
| **① 直连 HTTP 下载** | 队友与你**同一校园网/局域网** | 1~3 分钟（千兆内网） | 浏览器点链接下载 | ⭐⭐⭐⭐⭐ 最快，零上传 |
| **② Ollama 仓库推送** | 任何网络；队友只要能跑模型 | 取决于你的上行带宽 | `ollama pull <账号>/xjt-3b`（**完全不用碰文件**） | ⭐⭐⭐⭐⭐ 最省事 |
| **③ 夸克网盘** | 跨网络、队友习惯自己存文件 | 上传看上行，下载看队友是否会员 | 打开链接下载 → 校验 SHA256 → 本地 create | ⭐⭐⭐ 通用兜底 |
| **④ U 盘 / 移动硬盘** | 能线下见面 | 约 1 分钟 | 直接拷贝 | ⭐⭐⭐⭐ 见面就选它 |
| **⑤ GitHub Release** | 备用（需分卷，见第 6 节） | — | 下载分卷 → 合并 → 校验 | ⭐⭐ 较麻烦 |

**建议顺序：先试 ① → 不行用 ② → 都不行用 ③ → 能见面用 ④**

---

### 2.1 方案①：直连 HTTP 下载（推荐先试）

**分发方（你）**

```powershell
# 1) 起服务（会自动打印队友可用链接）
powershell -ExecutionPolicy Bypass -File ai/finetune/serve_gguf.ps1 -AllowFirewall
```

- 首次建议用**管理员 PowerShell** 运行，让脚本自动放行防火墙；
- 若队友连不上，手动放行：
  ```powershell
  netsh advfirewall firewall add rule name="XJT GGUF Share" dir=in action=allow protocol=TCP localport=8000
  ```
- 脚本会列出所有本机 IPv4 地址，例如 `http://49.140.103.171:8000/xjt-3b-f16.gguf`；

**接收方（队友）**

1. 浏览器（或 IDM / 迅雷）打开链接 → 保存为 `xjt-3b-f16.gguf`
2. 核对 SHA256（见第 1 节）
3. 执行一键部署（第 3.2 节）

**注意**：跨公网时需确保校园网/路由器未封禁该端口；传完按 `Ctrl+C` 停止服务，并删除防火墙规则：

```powershell
Remove-NetFirewallRule -DisplayName 'XJT GGUF Share'
```

---

### 2.2 方案②：Ollama 仓库推送（队友一键 pull，最省事）

把模型推到 Ollama 公共仓库后，队友**不需要任何文件**，直接 `ollama pull` 即可。

**分发方（你）**

```powershell
# 1) 登录 Ollama 账号（首次；浏览器授权，免费注册 https://ollama.com）
ollama signin

# 2) 复制一份带命名空间的模型（格式必须为 <账号名>/<模型名>）
ollama cp xjt-3b <你的账号名>/xjt-3b

# 3) 推送（约 6.2 GB，耗时取决于上行带宽）
ollama push <你的账号名>/xjt-3b
```

**接收方（队友）**

```powershell
ollama pull <你的账号名>/xjt-3b          # 直接得到完整模型，无需 GGUF/Modelfile
ollama run  <你的账号名>/xjt-3b "图书馆几点关门？"
```

后端配置：`XJT_OLLAMA_MODEL=<你的账号名>/xjt-3b`

> ⚠️ 免费账号推送的模型是**公开的**；若不便公开，请改用方案①③。

---

### 2.3 方案③：夸克网盘（通用兜底）

**分发方（你）**

1. 打开夸克网盘**客户端**（网页端传大文件易中断）→ 新建目录 `校捷通/xjt-3b/`
2. 上传 `E:\models\xjt-3b-f16.gguf`（5.75 GiB，主分发物）
3. 可选：再上传 `ai\finetune\out\qwen3b-lora\`（833 MB，给有 GPU 的队友自行合并）
4. 右键文件 → **分享** → 有效期选 **永久有效** → 生成链接与提取码
5. 把「链接 + 提取码 + SHA256」发到团队群，并填进**第 7 节登记表**

**接收方（队友）**

1. 打开链接 → 输入提取码 → 转存到自己网盘（可选，便于断点续传）
2. 下载 `xjt-3b-f16.gguf` 到本机
3. `certutil -hashfile xjt-3b-f16.gguf SHA256` 核对校验值
4. 执行一键部署（第 3.2 节）

> ⚠️ **夸克网盘非会员下载可能被限速**。若队友没有会员，6 GB 可能要等很久 —— 此时优先用方案① 或 ②。

### 2.4 方案④：U 盘 / 移动硬盘

能线下见面时最省事：直接拷贝 `E:\models\xjt-3b-f16.gguf`，队友侧照第 3 节部署。

## 3. 接收方操作（队友 · 下载并部署）


### 3.1 前置条件

- 已安装 [Ollama](https://ollama.com/download)（任意较新版本）
- **磁盘剩余空间 ≥ 15 GB**（GGUF 5.75 GiB + Ollama 复制一份约 6.2 GB）

### 3.2 一键部署（推荐）

```powershell
# Windows（在仓库根目录执行）
powershell -ExecutionPolicy Bypass -File ai/finetune/deploy_ollama.ps1 -GgufPath E:\models\xjt-3b-f16.gguf
```

```bash
# Linux / macOS
bash ai/finetune/deploy_ollama.sh ~/models/xjt-3b-f16.gguf
```

脚本会自动完成：**路径检查 → SHA256 校验 → 生成适配本机路径的 Modelfile → `ollama create` → 列出模型**。

### 3.3 手动部署（脚本不可用时）

```bash
# 1) 修改 ai/finetune/Modelfile 里的 FROM 为本机实际路径
FROM /your/path/xjt-3b-f16.gguf

# 2) 创建模型
ollama create xjt-3b -f ai/finetune/Modelfile

# 3) 验证
ollama run xjt-3b "图书馆几点关门？"
```

### 3.4 让后端用上微调模型

后端配置项为 `XJT_OLLAMA_MODEL`（`backend/app/core/config.py` 中 `ollama_model`，默认已改为 `xjt-3b`）。

在 `backend/.env` 中：

```dotenv
XJT_OLLAMA_MODEL=xjt-3b
XJT_OLLAMA_BASE_URL=http://127.0.0.1:11434
```

重启后端后，`POST /api/v1/chat/send` 即走真实微调模型（Ollama 未就绪时会优雅降级为占位回复，不阻塞开发）。

## 4. 验收标准

| 项 | 通过条件 |
|---|---|
| 模型存在 | `ollama list` 出现 `xjt-3b:latest`（约 6.2 GB） |
| 问答正确 | 问「图书馆几点关门？」能答出开放时间且不跑题 |
| API 可用 | `POST http://127.0.0.1:11434/api/chat` 返回 `message.content` |
| 后端联通 | `chat/send` 返回的回复来自模型而非占位文案 |

### 4.1 直连分发实测记录（2026-09-10）

| 项 | 数值 |
|---|---|
| 分发方 | 成员3 本机 `49.140.103.171`（网络类别 Public，1 Gbps 网卡） |
| 接收方 | 队友本机 `10.66.139.231`（校园内网） |
| 文件 | `xjt-3b-f16.gguf`，6,178,316,768 字节（5892.1 MiB） |
| 结果 | ✅ **完整传输成功**（落盘 5892.1 MiB） |
| 耗时 / 均速 | 1108.8 s（约 18.5 分钟）/ 约 5.3 MiB/s |
| 中断次数 | 3 次（`WinError 10053` 对端断开，校园网抖动） |
| 断点续传 | ✅ 生效：中断后自动从断点继续，无需重头下载 |
| 防火墙 | 无需管理员操作：复用已有 `E:\python314\python.exe` 的 Public 入站放行规则 |

**关键结论**：直连分发**必须**用 `gguf_server.py`（支持 Range 206）。
内置的 `python -m http.server` **不支持 Range** —— 实测请求 1 MB 却返回完整 6,178,316,768 字节（HTTP 200），
本例中队友若用它，3 次中断就要重下 3 次。

## 5. 常见问题（FAQ）

| 现象 | 原因 | 解决 |
|---|---|---|
| `only one usage of each socket address` | 已有 Ollama 服务在跑（正常现象） | 无需处理；确认 `http://127.0.0.1:11434` 可访问即可 |
| `not enough space on disk` | Ollama 默认模型目录在 C 盘 | 设置环境变量 `OLLAMA_MODELS=E:\ollama\models`（指向空间充足的盘）后重启 Ollama |
| `ollama create` 报 GGUF 解析失败 | GGUF 下载损坏 | 重新下载并核对 SHA256 |
| 回答跑题 / 答非所问 | 3B 小模型 + 采样温度偏高 | 使用仓库内新版 `Modelfile`（`temperature 0.4` + `top_p 0.9` + `repeat_penalty 1.1`）重建模型 |
| 后端仍返回占位文案 | 模型名不匹配或服务未启动 | 确认 `ollama list` 有 `xjt-3b`，且 `XJT_OLLAMA_MODEL=xjt-3b` |
| PowerShell 报「意外的标记」「字符串缺少终止符」 | `.ps1` 存成了 **UTF-8 无 BOM**，Windows PowerShell 5.1 按 GBK 解析导致中文乱码 | 用 VS Code 另存为 **UTF-8 with BOM**（本仓库脚本已含 BOM），或改用 `pwsh`（PowerShell 7）执行 |
| 队友下载中断后要重新下载 | 用了 `python -m http.server`（不支持 Range） | 改用 `ai/finetune/gguf_server.py`（`serve_gguf.ps1` 已默认调用它），支持 206 断点续传 |
| 队友打不开直连链接 | 防火墙未放行 / 跨网段 / 校园网封禁端口 | 放行 TCP 端口；仍不通则改用夸克网盘或 `ollama push` |

## 6. 备用分发通道：GitHub Release（受单文件 2 GiB 限制）

> ⚠️ **GitHub Release 单个附件上限 2 GiB**，而 `xjt-3b-f16.gguf` 为 5.75 GiB，**不能直接上传**。
> 必须分卷；否则请以**夸克网盘为主通道**。

### 6.1 分发方：分卷

```bash
# Git Bash / WSL / Linux / macOS
split -b 1900M xjt-3b-f16.gguf xjt-3b-f16.gguf.part-
sha256sum xjt-3b-f16.gguf.part-* > parts.sha256     # 记录各分卷校验值
```

Windows 无 `split` 时，用 7-Zip 分卷压缩（每卷 1900 MB）：

```powershell
& 'C:\Program Files\7-Zip\7z.exe' a -v1900m xjt-3b-f16.7z.001 xjt-3b-f16.gguf
```

### 6.2 分发方：发布 Release

1. 打开 <https://github.com/asuperj1/xiaojietong-project/releases/new>
2. Tag 填 `model-xjt-3b-v1`，标题填「xjt-3b 微调模型（GGUF 分卷）」
3. 附件上传**全部分卷**与校验文件（`parts.sha256`）
4. 说明栏粘贴**完整文件**的 SHA256：`f4edd5...75a3`（便于合并后校验）
5. 发布

### 6.3 接收方：合并与校验

```bash
# split 分卷
cat xjt-3b-f16.gguf.part-* > xjt-3b-f16.gguf

# 7-Zip 分卷：解压首个分卷即可自动合并
7z x xjt-3b-f16.7z.001
```

```powershell
# 合并后校验（Windows）
certutil -hashfile xjt-3b-f16.gguf SHA256
# 应等于 f4edd50b9d3759f8c742927a7dcf41ce979f8e2e7a93fceb6dccdb7131be75a3
```
