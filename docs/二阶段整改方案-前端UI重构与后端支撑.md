原方案是「一阶段工程 + 二阶段科研」两段式。产品方本次提出大规模 UI 重构与业务调整，
因此**阶段重新定义为三段**：

| 阶段 | 定位 | 内容 | 状态 |
|---|---|---|---|
| **一阶段** | 工程底座（中期 Demo） | 12 模块后端 + 29 页前端 + AI 三能力（RAG/Agent/微调） | ✅ **已完成**（PR #39/#42 已合并 `dev@bbb2ca9`） |
| **二阶段（本方案）** | **产品化整改** | **① 全局 UI 重构（液态玻璃 + 苹果风）② 5 大页面重构 ③ 后端支撑接口 ④ 外卖业务裁剪** | 🔵 **待开工** |
| **三阶段** | **科研深化** | 数据集构建 → 轻量信息抽取微调 → 基线对比实验 → 服务化（原"二阶段方向 1"） | ⚪ 二阶段完成后启动 |

**与原方案的关系**：

## 1. 全局 UI 统一规范（苹果风 + 液态玻璃）

### 1.1 视觉规范

| 维度 | 规范 | 实现要点 |
|---|---|---|
| **质感** | 液态毛玻璃（iOS 磨砂玻璃） | `backdrop-filter: blur(20px) saturate(180%)`；卡片/弹窗/TabBar/搜索框统一；**禁止厚重纯色块** |
| **底色** | 半透浅底 + 细微柔光 | `background: rgba(255,255,255,.62)`；叠加 `inset 0 1px 0 rgba(255,255,255,.6)` 高光边 |
| **阴影** | 柔和低对比 | `0 8px 24px rgba(31,38,135,.08)`，避免硬边投影 |
| **圆角** | 柔和 | 卡片 20rpx~28rpx；按钮 999rpx（胶囊）；输入框 24rpx |
| **主色** | 保留浅蓝 | `#4A90D9`（现主色，沿用）；悬停/激活加深 8% |
| **背景** | 淡粉渐变、低饱和 | `linear-gradient(160deg, #FDF6F8 0%, #F2F7FD 55%, #F6F4FC 100%)` |
| **文字** | 主/次两级 | 主 `#1F2329`（深灰）；次 `#8A9099`（浅灰）；禁用 `#C4C9D0` |
| **图标** | **苹果 iOS 线性图标** | 统一线宽 `1.5px`（对应 2rpx）；圆角端点；**禁用粗重填充** |

### 1.2 ⚠️ 小程序端兼容性降级（必做，否则低端机整片糊）

`backdrop-filter` 在微信小程序（尤其 **Android 低版本 WebView**）支持不稳定。**必须三层兜底**：

```css
/* 第一层：现代设备 —— 真毛玻璃 */
.glass {
  background: rgba(255, 255, 255, .62);
  -webkit-backdrop-filter: blur(20px) saturate(180%);
  backdrop-filter: blur(20px) saturate(180%);
  border: 1px solid rgba(255, 255, 255, .55);
  box-shadow: 0 8px 24px rgba(31, 38, 135, .08);
}
/* 第二层：不支持 backdrop-filter —— 提高底色不透明度模拟 */
@supports not ((backdrop-filter: blur(1px)) or (-webkit-backdrop-filter: blur(1px))) {
  .glass { background: rgba(255, 255, 255, .9); }
}
/* 第三层：运行时降级（JS 探测，见 §1.4） */
.is-glass-fallback .glass { background: #FFF; border: 1px solid rgba(0,0,0,.06); }
```

**判定与降级逻辑**（`app.js` 启动时执行一次）：

```js
// utils/glass.js —— 能力探测 + 全局降级开关
function detectGlass() {
  try {
    const info = wx.getAppBaseInfo ? wx.getAppBaseInfo() : wx.getSystemInfoSync()
    // 粗略判定：iOS 普遍支持；Android 低版本 WebView 保守降级
    const isIOS = /iOS/i.test(info.system || '')
    const ver = parseFloat(info.system.match(/Android\s+(\d+)/)?.[1] || '99')
    return isIOS || ver >= 9
  } catch (e) { return false }
}
module.exports = { detectGlass }
```

- 支持 → 真毛玻璃；不支持 → 半透明纯色（视觉仍有"轻"感，不牺牲可读性）
- **同时提供设置项**「减弱透明效果」（无障碍，兼顾性能）

### 1.3 动效规范（iOS 缓出）

| 交互 | 曲线 | 时长 |
|---|---|---|
| 页面滑入 / 侧边栏滑出 | `cubic-bezier(.25,.1,.25,1)` | 300ms |
| 搜索框上拉置顶 | `cubic-bezier(.34,1.2,.64,1)`（轻微回弹） | 320ms |
| 长按 / 按钮反馈 | `cubic-bezier(.4,0,.2,1)` + `scale(.96)` | 150ms |
| 列表项入场 | 依次 `translateY(12rpx)→0` + 淡入 | 240ms（错峰 40ms） |

> 小程序端统一走 `wx.createAnimation` 或 CSS `transition`；**避免 `setInterval` 手写动画**。

### 1.4 底部 TabBar 改造（需求 5）

| 项 | 现状 | 目标 |
|---|---|---|
| 导航项 | 5 个（首页/AI/服务/论坛/我的） | 保持 5 个，**AI 助手置于正中** |
| AI 按钮 | 普通图标 | **圆形放大按钮**（直径约 96rpx，上浮 20rpx，玻璃底 + 蓝色描边） |
| 长按 AI | 无 | **长按唤起语音转文字弹窗**（`wx.vibrateShort` 反馈 + 弹窗） |
| 图标 | 部分缺失/彩色 PNG | **全部换苹果线性图标**，线宽一致 |
| 实现 | 原生 `tabBar` | ⚠️ 原生 `tabBar` **无法**做凸起圆形按钮 → 改用 **自定义 TabBar**（`custom-tab-bar`） |

> ⚠️ **关键改造点**：凸起式中间按钮必须用**自定义 tabBar**（`app.json` 设 `"custom": true`）。
> 需注意：`custom-tab-bar` 在**部分页面 `tabBar` 隐藏场景**（如聊天页全屏）需手动控制显隐。

### 1.5 图标方案

现有 `ui/icons/navigation/` **缺 `user-solid.svg`**（PR #39 已记录）。
本轮统一改为线性图标集，建议：

- **来源**：Iconify 的 iOS 风格集（`solar:*-linear`、`tabler:*-outline`、`ph:*-light`）
- **落地方式**：**预先导出为本地 SVG**（不要运行时拉 CDN —— 原型页已因 `modao.cc` 被拦踩过坑）
- **线宽 / 尺寸**：统一 `stroke-width: 1.5`；TabBar 48rpx、功能卡 56rpx、列表 40rpx

## 6. 风险与注意事项

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| 1 | **`backdrop-filter` 兼容性** | 低端 Android 整片糊/掉帧 | 三层兜底（§1.2）+ 全局"减弱透明"开关 + 真机抽测 |

| 3 | **改表需重编译 C++** | 阻塞多人并行 | 4 项表变更**打包成一批**（§4 末尾） |
| 4 | **图标资源版权** | 商用风险 | 用 MIT/CC0 图标集（Tabler/Phosphor/Solar 免费版），**本地化导出** |
| 5 | **视觉重构回归面大** | 可能破坏已有功能 | 每个页面**独立分支 + PR**；重构前先补**冒烟清单** |
