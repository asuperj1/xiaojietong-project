## 0. 为什么要分成两类测试

| 对比项 | **A · 使用向测试** | **B · 技术性测试** |
|---|---|---|
| 视角 | 黑盒，用户视角 | 白盒，工程视角 |
| 执行人 | 非开发成员 / 指导老师 / 同学试用 | 成员3 为主，成员2、成员1 配合 |
| 回答的问题 | **"能不能用？好不好用？"** | **"对不对？稳不稳？安全吗？"** |
| 手段 | 真机操作小程序，按人生流程走 | 脚本 / 命令 / 压测 / SQL 核对 |
| 语汇 | 「我要发一个二手」「我要问 AI」 | 「HTTP 401 / 事务回滚 / p95 延迟」 |
| 产出 | 通过率 + 体验问题清单 | 通过/失败 + 指标数值 + 缺陷单 |
| 判定门槛 | **不需要技术背景即可判定**（看得见摸得着） | 需工程背景，以脚本输出为准 |

**为什么两者都必须做（本项目已验证的教训）**

1. **"接口全通" ≠ "功能正确"**：上一轮连通性测试 **23/23 全通过**，但其中 **5 个接口 `code=0` 却语义错误**（分页 `total` 填的是本页条数、状态文案错、丢字段）。
2. **"体验好" 掩盖不了越权**：审计实测「伪造 `X-Forwarded-For` 连发 15 次登录 → 0 次拦截」，这在 A 分册里**永远测不出来**。
3. 反过来，B 分册也测不出「分类 tab 点了没反应」「图片加载不出来」这类**用户一眼就炸**的问题。

> 结论：**两类测试互为盲区的补集**，缺一不可。执行顺序建议 **A 先于 B**（详见 §4）。

## 4. 执行顺序与节奏

```
第 0 步 · 冒烟（10 min）
   ├─ 环境自检（§3.5）
   ├─ pytest backend/tests -q                → 期望 7 passed
   └─ python tools/e2e_connectivity.py        → 期望 23/23
        ↓ 任一不过 → 停止，先修环境（不是软件缺陷）
第 1 步 · A 使用向测试（0.5~1 天）
   └─ 按人生流程走：登录 → 首页 → AI → 服务 → 论坛 → 我的
        ↓ 产出：通过率 + 体验问题清单（可含建议）
第 2 步 · B 技术性测试（1~1.5 天）
   └─ B1 契约 → B2 鉴权 → B3 错误码 → B4 并发 → B5 性能 → B6 AI → B7 数据层 → B8 异步 → B9 安全 → B10 工程 → B11 部署预检
        ↓ 产出：通过/失败 + 指标 + 缺陷单
第 3 步 · 缺陷回归（0.5 天）
   └─ 修复后只重跑"失败用例 + 关联用例"
第 4 步 · 出报告
   └─ `第一阶段验收测试报告.md`：结论 / 通过率 / 缺陷台账 / 已知遗留 / 是否放行
```

**为什么 A 先于 B**：A 分册发现的问题（tab 点击无反应、图片 403）会导致**大片用例无法执行**，先修完再进 B，避免 B 分册对着一个"半瘫"的系统做精细测量。

## 6. 缺陷分级与处理流程

### 6.1 分级定义

| 级别 | 定义 | 例子 | 处理要求 |
|---|---|---|---|
| **P0** | 阻断核心流程 / 数据错误 / 安全越权 | 登录不了、图片全 403、待审内容公开可见、可取消他人预约 | **当轮必修**，修完回归 |
| **P1** | 主要功能不可用但有绕行方案 | 分类 tab 失效（可换入口）、AI 定价偶发失败 | **验收前必修** |
| **P2** | 次要功能 / 体验问题 | 分页 `total` 不准、空 body 返回 422、文案不一致 | 记录，可带条件放行 |
| **P3** | 优化建议 | UI 微调、错误提示措辞 | 记录，不阻断 |

### 6.2 处理流程

```
发现 → 登记（C-测试记录表模板）→ 定级 → 指派（按模块）
     → 修复 → 提交（Conventional Commits，推对应 feature 分支）
     → 回归（重跑失败用例 + 关联用例）→ 关闭
```

**关键规则**
1. **缺陷必须登记到文档**，不得只留在聊天记录（沿用项目约定：`docs/技术方向待处理问题.md`）。
2. **修复必须走分支**，不得直接改 `dev`（沿用 `docs/团队Git合作协议.md`）。
3. **回归必须由"非修复者"执行**（避免自证清白）。
4. P2 及以下**允许带条件放行**，但必须写入验收报告的"已知遗留"章节。

| **B15 异步** | 默认 `XJT_CELERY_ENABLED=false`（eager） | **B-8 只测 eager 模式** | 异步需 Redis + 前端轮询，**本轮不测** |

### 7.3 明确豁免（本轮不做，不记缺陷）

- 登出失效（`SEC-07`）、refresh 无轮换（`SEC-08`）—— 需改表 + 重编译 C++，属专门批次
- 二阶段全部内容、端侧 `ai/edge/`、容器化/HTTPS 上线
- 多模态能力
