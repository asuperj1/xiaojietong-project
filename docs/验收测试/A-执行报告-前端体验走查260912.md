## 三、静态体验审查（前端代码）

### 3.1 分页 / 上拉加载

| 能力 | 覆盖页面 | 数量 |
|---|---|---|
| `onReachBottom`（上拉加载更多） | `forum/forum`、`job/index`、`secondhand/index` | **仅 3 个** |
| `onPullDownRefresh`（下拉刷新） | 上述 3 个 + `life/index`、`life/notices` | 5 个 |

**❌ 缺口：以下 12 个列表页无法上拉加载更多**（长列表只能看到第一页）：

```
agent/index（任务列表）      chat/history（会话列表）    forum/mine（我的帖子）
job/mine（我的投递）         library/index（场馆）       library/freeRoom（空教室）
library/myReserve（我的预约） life/index（商家）          life/notices（通知）
map/index（POI）             secondhand/mine（我的发布）  user/favorites（收藏）
```

> **影响**：后端已支持 `?page=&size=`（且列表数据会持续增长），但前端**只加载第一页**。
> 封测时若数据量不大（20 条内）不易暴露；**一旦数据超过一页，用户会以为"数据丢了"**。

### 3.2 错误处理 / 加载反馈

| 检查点 | 结果 |
|---|---|
| 空 `catch(() => {})` 吞异常 | ✅ **0 处**（`services/request.js` 已统一 `showToast`） |
| `wx.showLoading` / `hideLoading` | ✅ 有使用（如 `chat/history`），且成对出现 |
| 加载中遮罩 | ⚠️ 覆盖不全（多数列表页无 loading 态，仅靠页面初始渲染） |

### 3.3 兼容性

| 检查点 | 结果 |
|---|---|
| `new Date(...)` 解析字符串（**iOS 返回 Invalid Date 的经典坑**） | ⚠️ **1 处**：`pages/library/seat.js:5` `const d = new Date()` |
| 时间格式化 | ✅ 项目已有先例用**纯字符串截断**规避（`formatTime`），建议 `seat.js` 对齐同一做法 |
| 列表空 `items` 兜底 | ✅ 普遍使用 `((res && res.items) \|\| [])` |
