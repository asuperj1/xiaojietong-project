# 第一阶段验收 · A 分册｜使用向测试用例

> **配套**：`00-第一阶段验收测试方案.md`（准入条件 §2、环境准备 §3、判定 §5、豁免 §7）
> **执行人**：非开发成员 / 指导老师 / 同学试用（**不需要技术背景**）
> **判定原则**：只回答一句话 —— **"我看到的是不是预期看到的那样？"**
> **覆盖**：小程序 **29 个页面** + 12 个功能模块

---

## 一、怎么用这份用例

1. **每条用例只需打三个勾之一**：☐ 通过 ｜ ☐ 失败 ｜ ☐ 阻塞（前置条件不满足，测不了）
2. **失败必须留证据**：截图 + 一句话描述现象（"点了没反应"也算，但请写清"点了哪个按钮"）
3. **不要求你判断原因**，也不要尝试改代码 —— 把现象记下来就够
4. **跨账号验证时**：甲、乙、丙三个账号分别用不同设备/不同微信开发者工具窗口登录，**不要用同一账号来回切**
5. 遇到"符合预期但你觉得别扭"的地方 → 记到本册末尾的 **「体验建议区」**（不算缺陷，但很有价值）

### 执行前必须确认（否则会成片失败）

| # | 前置 | 怎么确认 |
|---|---|---|
| 1 | 前端 `BASE_URL` 已改为局域网 IP | 问成员1；或看能否打开首页 |
| 2 | 「不校验合法域名」已勾选 | 开发者工具 → 详情 → 本地设置 |

| 5 | **已知会失败的 3 项**（见主方案 §7.1）是否已修 | 若未修，相关用例直接标 ☐ 阻塞 |
