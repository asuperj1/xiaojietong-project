## 四、做得好的地方（客观记录）

审查中发现的**值得肯定的实现**，建议保留：

### 4.1 手写 UTF-8 部分解码器 ✅

`services/request.js` 的 `decodeUtf8Partial(bytes)` —— 正确解决了 **SSE 流式传输中中文字符跨 chunk 断裂导致乱码**的问题：

- 识别 1~4 字节 UTF-8 序列长度
- 遇到**不完整多字节序列**时停止解码，把尾部字节**留待下一个网络 chunk** 拼接
- 对损坏字节用替换符 `\ufffd` 容错，不中断整个流

> **这是多数实现会踩坑的地方**：直接用 `TextDecoder` 逐 chunk 解码，中文会被截成乱码。

### 4.2 登录失效统一处理 ✅

`handleAuthFailure()` 同时清理 **storage** 与 **globalData**，避免"存储态已清空但内存态仍有 token"的不一致状态。`request()` 与 `sseRequest()` 共用该函数，语义一致。

### 4.3 登录页边界处理完备 ✅

`pages/auth/login.js` 覆盖三条错误分支：`wx.login` 未返回 code / `wx.login` 调用失败 / 请求失败；并有 `loading` 标志**防重复点击**。

### 4.4 跳转 API 使用正确 ✅

- `login.js` 登录成功后用 `wx.switchTab` 跳首页 —— **正确**（首页是 TabBar 页面，用 `navigateTo` 会失败）
- `index.js` 宫格区分 `tab: true/false` 选择 `switchTab` / `navigateTo` —— **正确**

### 4.5 工程实践良好 ✅

### 4.6 F4 SSE 流式渲染实现质量高 ✅

`pages/chat/chat.js` 的几点做法值得肯定：

| 做法 | 价值 |
|---|---|
| **先插入用户气泡 + 空 AI 气泡，再流式填充** | 用户立即看到反馈，而非等首字节 |
| **`onUnload` 里 abort 未完成的 `RequestTask`** | 防止页面销毁后回调仍在写 `setData`（会报错） |
| **`_task` / `_localSeq` 用下划线前缀** | 明确标记"非渲染态字段"，不与 `data` 混淆 |
| **`updateMessage` 用精确路径 `messages[idx]` 而非整体替换** | 避免每次 chunk 都重渲染整个列表 —— **流式场景下这是关键性能优化** |
| **`onChunk` 追加而非覆盖**（`next = msg.content + delta`） | 正确实现逐字累加 |
| **`sources` 归一化为可安全渲染字段** | 避免直接把后端对象塞进模板 |
| **首页搜索衔接：读 `pendingSearch` 后立即清空** | 防止 `onShow` 多次触发时重复发送（虽然顺序有瑕疵，见问题 7） |
| **空回答兜底**（"（本次没有返回内容）"） | 模型返回空时用户不会一脸茫然 |

### 4.7 `sseRequest` 的边界处理细致 ✅

`services/request.js` 的 SSE 实现有以下细节：

- **「只触发一次 `onError`」** —— 防止网络错误与解析错误叠加导致重复回调
- **「主动 abort 属正常终止：静默结束，不当作网络错误」** —— 用户点停止或页面卸载时不弹错误 toast，**这个区分很到位**
- **文档注释齐全**（`@param` 逐项说明各回调的 payload 结构）
- 返回 `RequestTask` 供调用方 `abort()` —— 接口设计正确
