## 三、待修问题（按严重度排序）

### 🔴 问题 1：错误码 `2003` 未适配 —— 被禁用用户不会跳登录页

| 项 | 内容 |
|---|---|
| **位置** | `miniprogram/services/request.js` —— 登录失效判断处 |
| **现状** | 前端仅对 `code === 2001 \|\| code === 2002` 调用 `handleAuthFailure()`（清理登录态 + 跳登录页） |
| **后端实际** | `2001` 未登录(401) / `2002` token 失效(401) / **`2003` 无权限(403)** |
| **问题** | **后端 `2003` 现已用于「账号已禁用」**（审计 SEC-06 修复引入：`user_dao` 补齐 `status` 字段后，禁用账号校验才真正生效）。前端未把 `2003` 视为登录失效 → 被禁用的用户**停留在原页面反复看到报错 toast**，而不会被引导重新登录 |
| **复现** | 后端 `UPDATE user SET status=1 WHERE id=<uid>` 后，用该用户 token 调任意接口 → 返回 `HTTP 403 {code:2003, message:"账号已禁用"}`；前端只 toast |
| **建议修复** | 将 `2003` 一并纳入登录失效处理：<br>`if (code === 2001 \|\| code === 2002 \|\| code === 2003) { handleAuthFailure(message) }`<br>或更精细：`2003` 时提示「账号已被禁用，请联系管理员」后再跳登录页 |
| **来源** | **后端契约变化**（成员3 于 `caf17fa` 引入），非前端缺陷，但需前端同步 |

### 🔴 问题 2：`BASE_URL` 硬编码 `http://127.0.0.1:8000` —— 上线阻塞

| 项 | 内容 |
|---|---|
| **位置** | `miniprogram/services/request.js` 顶部：`const BASE_URL = 'http://127.0.0.1:8000/api/v1'` |
| **问题** | ① 微信小程序**不接受 http 协议**（`wx.request` 在真机/发布版会直接失败），仅在开发者工具勾选「不校验合法域名」时可用；② `127.0.0.1` 指向手机自己，真机上无法连通；③ 域名未配置时**无法提交审核** |
| **影响** | 当前状态**只能在开发者工具中调试**，无法真机预览、无法上线 |
| **建议修复** | 抽离为按环境切换的配置，例如：<br>`const BASE_URL = __wxConfig.envVersion === 'develop' ? 'http://127.0.0.1:8000/api/v1' : 'https://<正式域名>/api/v1'`<br>并在小程序后台配置 `request` 合法域名（需 https + ICP 备案） |
| **关联** | `docs/技术方向待处理问题.md` → `ARCH-03`（容器化 / Nginx / HTTPS / 域名） |

## 四、做得好的地方（客观记录）

审查中发现的**值得肯定的实现**，建议保留：

### 4.1 手写 UTF-8 部分解码器 ✅

`services/request.js` 的 `decodeUtf8Partial(bytes)` —— 正确解决了 **SSE 流式传输中中文字符跨 chunk 断裂导致乱码**的问题：

- 识别 1~4 字节 UTF-8 序列长度
- 遇到**不完整多字节序列**时停止解码，把尾部字节**留待下一个网络 chunk** 拼接
- 对损坏字节用替换符 `\ufffd` 容错，不中断整个流

> **这是多数实现会踩坑的地方**：直接用 `TextDecoder` 逐 chunk 解码，中文会被截成乱码。

### 4.2 登录失效统一处理 ✅

`handleAuthFailure()` 同时清理 **storage** 与 **globalData**，避免"存储态已清空但内存态仍有 token"的不一致状态。`request()` 与 `sseRequest()` 共用该函数，语义一致。

### 4.3 登录页边界处理完备 ✅

`pages/auth/login.js` 覆盖三条错误分支：`wx.login` 未返回 code / `wx.login` 调用失败 / 请求失败；并有 `loading` 标志**防重复点击**。

### 4.4 跳转 API 使用正确 ✅

- `login.js` 登录成功后用 `wx.switchTab` 跳首页 —— **正确**（首页是 TabBar 页面，用 `navigateTo` 会失败）
- `index.js` 宫格区分 `tab: true/false` 选择 `switchTab` / `navigateTo` —— **正确**

### 4.5 工程实践良好 ✅

- 宫格入口用 **data 数组渲染**，避免写 10 份重复 WXML
- 搜索关键词暂存 `globalData.pendingSearch`，供 F4 页面读取 —— **跨页面通信有设计**
- 注释明确标注任务边界（如"F3 不实现 SSE，留给 F4"）
