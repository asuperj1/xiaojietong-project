## 二、Bug 清单（全部由 **#76** 引入）

### 🔴 P0-1 · 列名与脚本自身 `CREATE TABLE` 矛盾 → 实测 ERROR 1054

| 表 | 脚本 `CREATE TABLE` 定义的列 | #76 改后 INSERT 的列 | 实测 |
|---|---|---|---|
| `home_banner` | `image` / `link_type` / `link_target` | `image_url` / `link_url` | `ERROR 1054: Unknown column 'image_url'` |
| `pickup_point` | `business_hours` / `status`（**无 `campus`**） | `open_time` / `campus` / `enabled` | `ERROR 1054: Unknown column 'open_time'` |

而 `dev` 版对应的 INSERT 是 **`(id, title, image, link_type, link_target, sort, enabled)`** 与 **`(id, name, address, business_hours, sort, status)`** —— 与建表定义**完全一致**。

### 🔴 P0-2 · 种子被「偷换」成另一套数据（新发现）

`dev` 版 `18_takeaway_pickup.sql` 的种子是 **3 条**：

```
菜鸟驿站·一食堂店 / 京东快递·图书馆店 / 顺丰驿站·三公寓店
```

而 #76 **换成了 5 条完全不同的驿站**：

```
三教快递柜 / 中心馆驿站 / 行政楼快递站 / 学生活动中心驿站 / 南区菜鸟驿站
```

**后果**：`WHERE NOT EXISTS (SELECT 1 FROM pickup_point)` 在表非空时**一条都不插、也不报错** —— 静默无效果；若表为空则会因 P0-1 的列名错误直接 ERROR 1054。**即这套新种子在任何情况下都不会生效。**

> 这 5 条驿站多半来自**另一个环境**，被误带进了本 PR。请作者确认来源。

### 🔴 P0-3 · 自检语句也被改错（第 3 处 ERROR 1054）

```diff
-SELECT ... SUM(`status` = 1) ...     -- dev 版
+SELECT ... SUM(`enabled` = 1) ...    -- #76
```

实测：

```
#76 版  → ERROR 1054 (42S22): Unknown column 'enabled' in 'field list'
dev 版  → pickup_point 行数 = 3，启用 = 3   ✅ 正常
```

`pickup_point` 的真实列是 `status`，**不存在** `enabled`。

### 🟠 P1 · 幂等写法相对 `dev` 是**降级**

`固定主键 + ON DUPLICATE KEY UPDATE`（真幂等：重跑=更新，可补齐）
→ `WHERE NOT EXISTS (SELECT 1 FROM 表)`（**整表空才插**）。

- `dev` 版 ODKU 能保证：改了种子内容 → 重跑会更新；缺行 → 重跑会补齐。
- #76 版：表非空后**既不更新也不补齐**，且**静默不报错**（比报错更难发现）。

### 🟡 P3 · 注释与代码矛盾

`15_home_banner.sql` 文件头仍写「种子用固定主键 + ON DUPLICATE KEY UPDATE」，代码却已改成 `WHERE NOT EXISTS`，且紧随其后又出现一条相反注释。

## 二·补 · 反转：种子**内容**上，#76 反而是对的（dev 版是死链）

把种子的**跳转路径**与 `miniprogram/app.json` 注册的真实页面对照：

`app.json` 里有 `pages/agent/index`、`pages/secondhand/index`、`pages/service/service`；**没有** `pages/ai/index`、`pages/notice/index`、`pages/second/index`。

| 版本 | `home_banner` 种子跳转路径 | 判定 |
|---|---|---|
| `dev`(#74) | `/pages/ai/index`、`/pages/notice/index`、`/pages/second/index` | ❌ **三个全是死链**（页面未注册 → 点击轮播 `navigateTo` 失败） |
| #76 | `/pages/agent/index`、`/pages/secondhand/index`、`/pages/service/service` | ✅ **三个都指向真实页面** |

**结论修正**：#76 **并非全错** —— 它的**种子内容是一次真实修复**（修掉了 #74 的死链缺陷）；错的是**写法**（列名 + 幂等 + 自检）。正确处置是"**保内容、改写法**"，而非关闭。

> 这也顺带暴露了 `dev`(#74) 的一个**真实业务缺陷**：轮播种子指向 3 个不存在的页面。这是 B19 真正需要修的点。
