## 二、评论正文（已发布）

```markdown
@后端组 B15 看到了（`8710449`），结论：**设计挺稳**，但上一轮那条 P1 还没修，仍在合并前要处理。

**✅ B15（Celery + Redis）做对的地方**

1. **降级而非硬依赖** —— `task_always_eager = not settings.celery_enabled`，默认 `XJT_CELERY_ENABLED=false`，
   无 Redis 也能跑（`.delay()` 就地同步），响应与旧版**完全一致**（`return ok(task.result)`）。
   「一键切换 + 不破坏现有链路」这个取舍是对的。
2. **`_ensure_db()` 抓住了真坑** —— worker 是独立进程、**不跑 FastAPI lifespan**，
   不惰性初始化连接池的话所有 `cpp_bridge` 调用都会炸。注释也写清了 👍
3. **`redis>=4.5.2,<5` 的版本锁定 + 原因注释**（redis-py 5.x 协商 RESP3 `HELLO`，
   与 Windows 常用 Redis 5.0.14 不兼容）—— 这种「踩过的坑写进依赖注释」的习惯建议保持。
4. `create_task` / `knowledge_index` 由 `async def` 改 `def`（走线程池）是**正确方向**，
   避免同步阻塞事件循环；`docs/api.md` v1.13、`.env.example` 三项、`/health/detail` 的 `celery` 字段都同步了 ✓

**⚠️ P1 仍未修（合并前唯一阻断项）**

上一轮的**上传签名「只写不读」**在 `8710449` 中没有变化：

- `backend/app/core/config.py:79` 仍是 `upload_signed_url_enabled: bool = True`
- 全仓仍**无 `resign` 实现**
- `routers/secondhand.py` / `routers/favorite.py` / `routers/user.py` 返回图片、头像时**仍是入库裸路径**

结论不变：**前端一接上上传，商品图 / 收藏图 / 头像就会 403**（现在没炸只是因为还没人用上传链路）。
最小修法仍是二选一：

1. `upload_signed_url_enabled` 默认改 `False`（1 行），在 `api.md` 注明启用前提；
2. 补 `storage.resign(url)`：识别 `/static/uploads/` 前缀后重新签名
   （别直接复用 `url_for`，它会把完整路径拼成 `/static/uploads//static/uploads/xxx.jpg`），
   在返回图片字段前统一调用。

**这条不解决，建议先别合。**

**🆕 B15 新引入的 3 条（P2，不阻断，建议同批处理）**

1. **`task_eager_propagates=True` 把新失败模式暴露成 500** —— eager 下任务内异常会从 `.delay()`
   直接抛回路由。最典型的是 `_ensure_db()` 在 `jt_db` 扩展不可用时 `raise RuntimeError` →
   `/agent/tasks`、`/admin/knowledge/index` 返回 **HTTP 500**，而非 `{code,message,data}` 契约错误。
   建议把 `.delay()` 包一层 try/except → 转成 `err_server` 契约响应。
2. **eager 同步跑在线程池里** —— `create_task` 现在是同步路由，eager 时整条三级链路
   （模型调用 timeout 120s）实占一个 anyio 线程（默认上限 40）。并发一高会**连带拖慢其它同步路由**。
   建议给 Agent 显式超时，或收紧 `/agent/tasks` 限流。
3. **`index-status` 在 `XJT_CELERY_ENABLED=false` 时恒为 `PENDING`** —— eager 且未开
   `task_store_eager_result` 时结果不进后端 → 任意 `task_id` 查询都返回 `state=PENDING`，
   容易被误读为「还在跑」。docstring 已说明用途，建议再补一句「未启用异步时该接口无意义」。

**📝 描述建议更新**

描述末尾「剩余：B15（Celery + Redis 异步化）待排期」**已过时** —— B15 就是本 PR 最新提交 `8710449`。
建议补 B15 条目并说明「默认关闭、需 Redis + worker、Windows 须 `-P solo`」，同时把「剩余」更新为 B16+。

**合并预检**：`dev ← feature/backend`（新 head `8710449`，merge-base `4deceab`）**无冲突**，可干净合并 ✅

**总评**：B15 的降级设计我认为可以放心合；**唯一门槛还是那条 P1 签名闭环**。
```
