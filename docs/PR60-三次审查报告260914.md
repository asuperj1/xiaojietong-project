## 1. P1 `purge` 护栏 —— 修得对，且我做了**变异反向对照**

### 代码（`services/knowledge.py`）

```python
MIN_PURGE_PREFIX_CHARS = 3

def like_prefix_pattern(prefix: str) -> str:
    escaped = prefix.replace("\\", "\\\\").replace("%", "\\%").replace("_", "\\_")
    return escaped + "%"
```

- **转义顺序正确**（`\` 先于 `%`/`_`）—— 顺序错了就会把刚加上的转义符再转一遍；
- SQL 用 `LIKE ? ESCAPE '\\'`，MySQL 解析 `'\\'` → 单反斜杠 `\` 作转义符，**正确**；
- `normalize_source()` 已把 `\` 归一成 `/`，故 `\` 转义冗余但无害；
- `len(p) < 3` → `raise ValueError`；`dry_run` 只统计不删；返回体新增 `pattern`/`dry_run`。

## 3. 🔴 阻断项（新）：本 PR 的 3 个 `.ps1` 全部缺 UTF-8 BOM

### 事实

| 文件 | 来源 | dev | BOM | Windows PowerShell 5.1 解析错误 |
|---|---|---|---|---|
| `backend/tests/gen_kb_bench.ps1` | **本 PR 新增** | 无 | **无 BOM** | **17** |
| `backend/tests/make_kb_pdf_samples.ps1` | **本 PR 新增** | 无 | **无 BOM** | **2** |
| `backend/tests/verify_b16_b18.ps1` | **本 PR 新增 + 本次修改** | 无 | 旧版**有 BOM** → 新版**无 BOM** | 旧 **0** → 新 **13** |

仓库既有约定（`dev` 上 4 个 `.ps1`）**全部有 BOM、解析错误 0**：

```
backend/tests/verify_b2.ps1                     有BOM  err=0
db/cpp_driver/scripts/build.ps1                 有BOM  err=0
db/cpp_driver/scripts/reset_mysql_password.ps1  有BOM  err=0
db/cpp_driver/scripts/restore_myini.ps1         有BOM  err=0
```

### 归因（已用反向对照坐实）

**仅把 BOM 补回、内容一字不改** → 语法错误 **13 → 0**。所以唯一原因就是缺 BOM。

**机制**：Windows PowerShell 5.1 对**无 BOM** 的 `.ps1` 按系统 ANSI（GBK/936）读取。
UTF-8 中文占 3 字节，被当 GBK 解析时，后面的 ASCII 字节若落在 GBK 尾字节区间
（`0x40–0x7E`）就会被吞掉 —— 而 **`{`=0x7B、`}`=0x7D 正好在这个区间**，
于是报「语句块或类型定义中缺少右 `}`」。受影响行示例：

```
L79:  foreach ($f in $files) {
L99:  } catch {
L129: Write-Host "== B17) 批量导入管道（命令行） =="
```

### 后果

- 本机（团队默认环境，仅有 Windows PowerShell **5.1**，**未装 pwsh**）**这 3 个脚本一个都跑不了**；
- 作者很可能是用 **PowerShell 7+** 跑的（7+ 默认 UTF-8，无 BOM 也能解析）→ 所以自己没发现；
- 于是**二次审查要求补的那套 ps1 反向对照（`$pubBefore`/`$pubAfter` 集合对比 + 非空断言）成了死代码**；
- `gen_kb_bench.ps1` 是 **B17 基准语料唯一的生成入口**，`make_kb_pdf_samples.ps1` 是 **B16 样本生成入口** —— 都跑不了。

### 修法（三选一，推荐第 1 个）

1. **给这 3 个文件加回 UTF-8 BOM**（与仓库既有 4 个 `.ps1` 保持一致）；
2. 把脚本内中文改成 ASCII（影响可读性，不推荐）；
3. 全组统一改用 PowerShell 7+，并把「需 `pwsh`」写进 `docs/DEVELOPMENT.md`（但那就要保证人人装了 pwsh）。

> ⚠️ 提交前请**实跑一遍**并贴输出：`powershell -NoProfile -ExecutionPolicy Bypass -File tests/verify_b16_b18.ps1`
