## 二、P1：release 未配置时是**同步抛错**，`.catch()` 与 `onError` 都接不到

### 2.1 根因

`getBaseUrl()` 在 `new Promise(...)` **之前**求值：

```js
function request(path, { method = 'GET', data = {} } = {}) {
  const url = getBaseUrl() + (path.startsWith('/') ? path : '/' + path)  // ← 同步调用
  // ... 中间还有 token 读取
  return new Promise((resolve, reject) => { ... })                       // ← Promise 还没被创建
}
```

异常在**求值 `request(...)` 这个表达式时**就抛出，`.catch()` 根本没有机会挂上去。
`services/request.js:167`（`sseRequest`）是同一写法。

### 2.2 实测证据（Node 实跑分支上的 `config/env.js`）

条件：`wx.getAccountInfoSync()` 返回 `envVersion='release'`、`wx.getStorageSync()` 返回 `''`（即 `RELEASE_BASE_URL` 未配置）。

```
[A] 调用方写了 .catch()  ->  .catch 被触发? false ; 同步逃逸? YES
    逃逸信息: [env] release 环境未配置正式 API 地址：请在 miniprogram/config/env.js 的 RELEASE_BASE_URL 中填写
[B] 调用方没写 .catch()  ->  同步逃逸? YES
[C] sseRequest           ->  onError 被调用? false ; 拿到 task? NO ; 同步逃逸? YES
```

### 2.3 影响面（精确统计）

`miniprogram/pages` 下 `request()` / `sseRequest()` **调用点 = 52 处**，`.catch(` **出现 = 47 次**。

**这 47 处 `.catch` 一个也接不住** —— 不是它们写得不对，而是**异常根本走不到 Promise 那一层**
（`getBaseUrl()` 在 `new Promise(...)` 之前求值，表达式求值阶段就抛了）。

> 📌 **统计口径更正**：本节初稿曾写作「42 处写了 `.catch`」，那是**按文件近似**的结果
> （每文件 `.catch` 数 ≥ 调用数则整文件计入）。**精确值：52 处调用 / 47 次 `.catch(`**。
> 已在 PR 评论区同步更正。

**补充硬证据**：`services/request.js` 内部共 **6 处 `wx.showToast`**
（`L44` / `L76` / `L101` / `L106` / `L265` / `L280`），在 release 未配置场景下**也全都不会触发** ——
它们都在 `wx.request` 的 `success` / `fail` 回调里，而 `getBaseUrl()` 抛出时 **`wx.request` 压根没有被调用**。

⇒ 症状是**彻底的静默**：没有 toast、没有 modal、没有 `onError`、`.catch` 也不触发。

用户可见后果最典型的是对话页 `pages/chat/chat.js:154`：

| 行 | 内容 | 后果 |
|---|---|---|
| `L148` | `this.setData({ sending: true })` | 已执行 |
| `L154` | `this._task = sseRequest(...)` | **同步抛出 → 外层函数中断** |
| `L196` | `onError: () => { ...setData({ sending: false }) }` | **永不执行** |

→ **症状：点发送后永久 loading、AI 气泡空白、没有任何错误提示**（toast 也不会弹，见上）。

> 补充澄清：`chat.js:57 abortTask()` 有 `this._task &&` 保护，所以**不会** TypeError；
> 问题纯粹是"状态机卡住 + 无提示"，不要误判成空指针。

### 2.4 建议最小改法（不改变设计取舍，两处各 3 行）

```js
// ---- request() ----
function request(path, { method = 'GET', data = {} } = {}) {
  let url
  try {
    url = getBaseUrl() + (path.startsWith('/') ? path : '/' + path)
  } catch (e) {
    // 让调用方的 .catch() 能接住；并给用户可见反馈（比静默卡死好排查太多）
    wx.showToast({ title: '接口地址未配置，请联系管理员', icon: 'none' })
    return Promise.reject(e)
  }
  // ...以下不变
}

// ---- sseRequest() ----
function sseRequest(path, data = {}, { onSources, onChunk, onDone, onError } = {}) {
  let url
  try {
    url = getBaseUrl() + (path.startsWith('/') ? path : '/' + path)
  } catch (e) {
    if (typeof onError === 'function') onError(e)
    return { abort() {} }   // 保持 RequestTask 形状，调用方 task.abort() 不炸
  }
  // ...以下不变
}
```

**再加一条更根本的**：在 `app.js` 的 `onLaunch` 里 `try/catch` 调一次 `getBaseUrl()`，失败时
`wx.showModal` 给明确文案 —— 这样**第一次冷启动就暴露**，而不是等用户点到某个按钮才炸。
这才是 `fail fast` 应有的效果。

## 三、P2（建议本 PR 一并处理）

### P2-1 `RELEASE_BASE_URL` 不校验协议，缺 scheme 会静默放行

实测 `normalizeBaseUrl()` 边界：

| 输入 | 输出 | 判定 |
|---|---|---|
| `"https://api.x.edu.cn/api/v1/"` | `"https://api.x.edu.cn/api/v1"` | ✓ 正确 |
| `"  https://api.x.edu.cn/api/v1  "` | `"https://api.x.edu.cn/api/v1"` | ✓ 正确 |
| `"https://"` | `"https:"` | ✗ **静默产出非法地址** |
| `"http://"` | `"http:"` | ✗ 同上 |
| `"api.x.edu.cn/api/v1"` | `"api.x.edu.cn/api/v1"` | ✗ 缺 scheme 也放行 |

**建议**：release 分支加两行断言 —— 非 `https://` 开头直接抛"正式地址必须是 https"的专用错误。
微信正式版强制 https，早失败远比 `wx.request` 报 `url not in domain list` 好排查。

### P2-2 方案文档 `docs/前端上线-域名与HTTPS方案.md` §4 未同步（会误导后来人）

该文档是**现行方案文档**（不是历史快照），但 §4 现在仍写着：

- 新建 `miniprogram/`**`config.js`**（本 PR 实际是 `config/`**`env.js`**）
- `module.exports = { BASE_URL: resolveBaseUrl(), ENV_CONFIG }`
- `request.js` 改为 `const { BASE_URL } = require('../config.js')`

而本 PR **已经不再导出 `BASE_URL`**。照着文档做的人会拿到 `undefined`。
PR 已同步 `miniprogram/README.md` 与 `miniprogram/前端页面规格.md` ✓，**只差 `docs/` 下这一份**。

### P2-3 `trial` 允许 storage 覆盖 —— 与"便于真机调试"这个理由对不上

按微信定义，**预览 / 真机调试都属于开发版（`envVersion = 'develop'`）**，`trial` 是体验版。
所以"便于真机联调局域网后端"只需放 `develop` 即可。

保留 `trial` 的实际效果是：**体验版包可以被改指向任意地址** —— 而封测阶段体验版正是发给测试者的。
**待确认**：这是有意为之（让测试者能连测试服务器），还是顺手写的？
若是后者，建议收窄为 `envVersion === 'develop'`。
