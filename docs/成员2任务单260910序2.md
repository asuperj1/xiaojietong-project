## 一句话诊断（为什么要做这些）

当前后端：**业务 CRUD 成熟度高，AI 层可跑但静默降级，工程化/安全滞后**。最影响演示的 5 个点：

1. **发帖后浏览不到** —— `create_topic` 写 `audit_status=0`，而 `GET /topics` 只返回已审核 → 发帖→浏览闭环默认不成立（`forum.py:25,35`）。
2. **Agent 降级"假成功"** —— 模型不可用时置 `status=2`（成功）却**不动任何库表**（`agent.py:70-84`）。
3. **降级不可观测** —— `/health` 只报 db/cpp_ext，**看不出**当前是真 RAG 还是关键词 LIKE（`health.py:12-21`）。
4. **三处 AI 展示点最弱** —— 二手 AI 描述是硬编码 30/20 元（`secondhand.py:102-117`，且发布丢 `images`）、通知仅按年级过滤（`life.py:111`）、推荐纯时间序（`forum.py:57`）。
5. **安全/工程基线缺失** —— 无自动化测试、无 `.env.example`、`requirements.txt` 缺 `pyjwt`、无限流、CORS 全开且带 credentials、chat 会话存在越权（`chat.py:131-139`）。

## 🔴 B6 · 内容审核闭环（P0 · 今日必达）

**要解决的问题**：发帖默认不可见，唯一放行靠管理员手工调接口，演示时"发完帖看不到"。

| 产出 | 具体要求 |
|---|---|
| ① 审核服务 | 新增 `backend/app/services/audit.py`；新增建表脚本 `db/sql/11_audit.sql`（表 `audit_word`：词、级别、动作） |
| ② 审核逻辑 | `check(text) -> {passed, level, reason}`：命中敏感词表 → 拒绝；可疑词 → 待审；正常 → 通过。**可选**二次判定调 `xjt-3b`，超时/失败自动降级为规则，**不得阻塞发帖** |
| ③ 接入点 | `forum.py: create_topic` / `POST /topics/{id}/comments`；`secondhand.py: publish` |
| ④ 状态语义 | 通过 → `audit_status=1`（立即可见）；拒绝 → `audit_status=2` + 返回错误码 **3003**（在 `core/response.py` 登记） |
| ⑤ 发布者反馈 | 发帖响应回传审核结果；新增 `GET /forum/topics/{id}/audit-status` 供前端轮询 |
| ⑥ 后台提效 | `admin.py` 待审列表支持**批量通过/拒绝** |

**验收（必须当场演示）**
- 用干净文本发帖 → 换一个账号 `GET /topics` **立即可见**；
- 用含敏感词文本发帖 → 被拒 + 返回 3003；
- 管理员在 `/admin/forum/audit` 能批量处理待审。

## 🔴 B7 · Agent 降级语义修正（P0 · 明日必达）

**要解决的问题**：模型没起时，Agent 报"成功"但没有真实业务效果 —— 这是**答辩最容易被抓的漏洞**。

| 产出 | 具体要求 |
|---|---|
| ① 规则执行器 | 新增 `backend/app/services/rule_executor.py`，正则解析并**真写库**：<br>「X 点/分钟后提醒我 Y」→ `add_reminder`<br>「帮我预约 X 馆 Y 点的座位」→ `reserve_seat`<br>「查一下 X 馆空教室」→ `query_free_room`<br>「出一本 X，Y 元」→ `post_secondhand` |
| ② 三级链路 | 模型可用 → Function Calling（现状）；模型不可用 → **规则执行器**；两者都不中 → `status=3`（失败）+ `error_msg` |
| ③ 禁止假成功 | 移除「未执行任何工具却置 `status=2`」的路径 |

**验收**
- **停掉 Ollama** 后发「10 分钟后提醒我交作业」→ `reminder` 表**真的新增一行**，任务 `status=2`；
- 发无意义指令（如「今天天气不错」）→ 返回 `status=3` 而非假成功。
