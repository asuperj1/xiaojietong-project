# ICP 备案期间守则 · 全员必读

> **读者**：团队 **4 个人全部**（不只负责人）。
> **什么时候看**：拿到访问地址和令牌**之前**必须先读完；之后每次动手前扫一眼「红线卡」。
> **一句话原则**：
>
> ### 🔴 备案没下来之前，这台服务器上跑的只能是「我们自己用的接口」，不能是「打开就能看的网站」。

---

## 一、为什么要守这些规矩（30 秒版）

| 事实 | 含义 |
|---|---|
| 服务器在国内，**ICP 备案还在审核中** | 法律上**还没资格**对外提供互联网信息服务 |
| 我们用的是**公网 IP + 8080 + 访问令牌** | 有身份校验、没有域名 → 属于「内部接口」，不是「网站」 |
| 一旦改成 80/443、绑域名、装证书 | 就从「内部接口」变成 **「未备案的网站」** → **明确违规** |

**判断标准不是「有没有域名」，而是「是否面向不特定公众提供了网站服务」。**

**后果**（真实会发生）：
- 服务器被云厂商**强制关停**、公网 IP 被封、账号被清退（不提前通知）
- 域名进黑名单，**影响后面正式备案**（可能被驳回或延长）
- 影响**省级评审**材料和学校声誉
- 辛苦做的项目，不要因为改一个端口翻车

## 三、我能做什么 / 不能做什么（对着找自己）

### ✅ 可以做

| 场景 | 怎么做 |
|---|---|
| 我自己调接口 | `curl -H "X-Access-Token: <令牌>" http://122.51.248.93:8080/api/v1/xxx` |
| 前端/小程序联调 | 基地址填 `http://122.51.248.93:8080/api/v1`，请求头加 `X-Access-Token`；微信开发者工具勾「不校验合法域名」 |
| 让别的同学看一眼效果 | **屏幕共享**或当场演示；不要给地址 |
| 提代码、跑测试 | 正常走 GitHub PR → `dev`；服务器上 `08-deploy.sh` 拉最新 |
| 灌测试数据 | 可以，但**别灌真实用户信息** |
| 老师/评委要看 | 用**本机 + 屏幕共享**，或走学校内网；不要为了演示开公网 |

### ⛔ 不能做（含常见的「我以为没事」）

| 我可能会想… | 为什么不行 |
|---|---|
| 「就临时开一下 80，演示完就关」 | **「临时」也是违规**，云厂商的检测是自动的，几分钟就可能触发 |
| 「绑个免费域名更方便记」 | 有域名 = 典型「未备案网站」，风险最高的一类 |
| 「弄个 Let's Encrypt 免费证书，反正不要钱」 | 为对外服务做准备**本身就是规避意图证据** |
| 「用 ngrok 穿透到本机，不占服务器」 | **明确规避备案**，最严重 |
| 「把令牌发群里方便大家」 | 群里可能有外人；令牌泄露 = 门禁失效，任何人都能访问 |
| 「把 IP 和令牌写进 README 好协作」 | **公开仓库 = 全网可见**，等于把门锁钥匙挂门上 |
| 「反正是测试库，用真学号数据也没事」 | 明文 HTTP 传输 + 未备案，数据泄露风险叠加 |
| 「我改个端口不影响别人」 | 影响**全队**（可能直接导致服务器被封、备案被拒） |

## 四、用令牌的纪律

| 规则 | 说明 |
|---|---|
| **只通过私聊/当面**拿到令牌 | 如果有人把令牌发到群里，**立即提醒他撤回，并通知负责人轮换** |
| **不要截图令牌** | 截图会进相册/云盘，等于二次泄露 |
| **不要写进代码** | 放本地私有配置（如 `.env.local`，并确认已在 `.gitignore` 里） |
| **不要把带令牌的 URL 发出去** | `?access_token=xxx` 形式的链接**任何人点开都能用** |
| **令牌疑泄露 → 立刻告诉负责人** | 负责人会重新生成并通知全员（比被封服务器便宜太多） |

## 五、发现异常怎么办（3 步）

有人做了不该做的事，或者你怀疑被扫了：

1. **立刻说**——在团队群里 @ 负责人，说明「谁做了什么/看到了什么」。
   **不要**自己偷偷改回去（会掩盖问题、也可能改坏）。
2. **负责人处置**：
   - 端口/证书/域名/隧道类 → **立即回滚**（停服务、删配置、恢复原状）
   - 令牌泄露 → **立即轮换**
   - 被扫描/被访问 → 收紧安全组来源 IP + 看日志
3. **事后复盘**：在群里说清「为什么发生 / 怎么避免」，不追责但**要留痕**。

**自查命令**（负责人跑，其他人可以提醒他跑）：
```bash
sudo ss -lntp | grep -E ':(80|443)\b'        # 期望：无输出
systemctl is-active nginx apache2 httpd 2>/dev/null   # 期望：非 active
ps -ef | grep -Ei 'frp|ngrok|cloudflared' | grep -v grep   # 期望：无输出
```

## 六、这个阶段的边界（说清楚免得猜）

| 项 | 现状 |
|---|---|
| 域名 | ❌ 不使用 |
| HTTPS | ❌ 不使用（**明文 HTTP**） |
| 网站 / 网页 | ❌ 不提供 |
| 小程序正式发布 | ❌ 不发布（审核也需要备案域名） |
| 数据库公网访问 | ❌ 不可达（只绑 `127.0.0.1`） |
| 对外可访问范围 | ⚠️ **仅 4 人的出口 IP** 能连 8080（安全组限制） |
| 能传什么数据 | ⚠️ 只传**测试数据**，不要传真实敏感信息 |
| 什么时候能改 | **备案通过后**，由负责人**单独立项**改造（域名 + HTTPS） |

> ⚠️ **明文 HTTP 的现实影响**：同一网络链路上的设备理论上能窃听。
> 所以：**不要传真实手机号/学号/密码**，用测试账号。

## 七、备案下来之后

| 状态 | 动作 |
|---|---|
| 审核中（现在） | 保持现状，**不对外做任何动作** |
| **备案通过** | ① 确认备案号下发；② 由负责人**单独立项**做域名 + HTTPS 正式方案；③ **不要**在这套环境直接改端口或绑域名 |
| 备案被驳回 | 排查材料/主体问题；**在通过前继续保持现状** |
| 临时要给外部看 | **不要**开公网 —— 用屏幕共享 / 学校内网 |
