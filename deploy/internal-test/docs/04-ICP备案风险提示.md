# 04 · ⚠️ ICP 备案风险提示（**必读，红线级**）

> 本文是本部署方案的**合规依据**。任何人执行部署前必须先读完本文。
> 项目背景：**国内云服务器，ICP 备案审核中，仅 4 人团队内部联调自测。**

---

## 🔴 核心结论（一句话）

> **备案完成前，这台服务器上跑的东西「只能是团队自己用的接口」，
> 不能是「任何人打开浏览器就能看到内容的网站」。**

判断标准不是「有没有域名」，而是 **「是否面向不特定公众提供了网站服务」**。
把后端监听改成 80/443、或者给 IP 绑个域名，就从「内部接口」变成了
**「未备案提供互联网信息服务」** —— 这是明确的行政违规。

---

## 一、法律与监管依据（简述）

| 依据 | 要点 |
|---|---|
| 《互联网信息服务管理办法》 | 从事**经营性**互联网信息服务需取得 **ICP 经营许可证**；非经营性需**备案** |
| 《非经营性互联网信息服务备案管理办法》 | 未备案**不得**从事互联网信息服务；不得在备案前对外提供服务 |
| 《计算机信息网络国际联网管理暂行规定》 | 未履行备案手续，**不得**从事互联网信息服务 |
| 云服务商《服务协议》《备案服务条款》 | 阿里云/腾讯云等均明确：未备案即对外提供服务，平台有权**关停/封禁/清退**，并配合主管部门处置 |

> 上述为**监管框架要点**，不构成法律意见；如有争议以主管部门口径为准。

---

## 二、本方案为什么是合规的（设计依据）

| 我们做了什么 | 为什么合规 |
|---|---|
| 只使用 **8080** 端口 | 未使用 80/443 这两个「网站服务标准端口」，不构成对外网站形态 |
| **不绑定域名** | 无域名即无「网站」标识；访问者需知道 IP + 端口 + **访问令牌**才能用 |
| **不安装 Nginx/Web 服务器** | 不存在对外提供网页/静态站的能力 |
| **不申请 SSL 证书** | 无 HTTPS，不构成「可正常对公众访问的站点」 |
| **访问闸门 `X-Access-Token`** | 有**身份校验**，非「不特定公众可访问」 |
| **安全组限制来源 IP** | 访问面收敛到团队 4 人 |
| **不做内网穿透 / 隧道** | 未规避备案流程 |
| 使用人数 **4 人** | 内部开发自测，非「面向公众提供服务」 |

## 三、❌ 禁止事项清单（触线即须立即回滚）

| # | 禁止行为 | 风险 |
|---|---|---|
| 1 | 把监听端口改成 **80** | ⚠️ 直接构成「未备案提供网站服务」，最高风险 |
| 2 | 监听 / 放行 **443** | ⚠️ 同上（且若再装证书，属「已就绪对外服务」，更敏感） |
| 3 | 给服务器 **绑定域名** 或加 **A 记录** | ⚠️ 以域名对外 = 典型「未备案网站」 |
| 4 | 申请 / 安装 **SSL 证书**（certbot / acme.sh 等） | ⚠️ 为对外服务做准备，属规避意图证据 |
| 5 | 安装 **Nginx / Apache / IIS** 并对外 | ⚠️ 具备网站服务能力 |
| 6 | 把 **3306 / 6379** 暴露公网 | ⚠️ 数据安全事件，且平台会告警 |
| 7 | 使用 **frp / ngrok / cloudflared / SSH 反向隧道** | ⚠️ **明确规避备案**，最严重的意图性问题 |
| 8 | 把 IP:8080 **发到公开群 / 论坛 / 社交平台** | ⚠️ 扩散访问面 → 可能被认定面向公众 |
| 9 | 把 `XJT_ACCESS_TOKEN` 公开 | ⚠️ 闸门失效，等价于无鉴权对公众开放 |
| 10 | 在此环境部署**真实用户数据 / 生产数据** | ⚠️ 明文 HTTP + 未备案，数据风险叠加 |
| 11 | 用 IP:8080 做**任何形式的对外推广、引流、演示直播** | ⚠️ 直接构成「向公众提供服务」 |
| 12 | 关闭访问闸门（`XJT_ACCESS_TOKEN` 置空）后继续保留公网访问 | ⚠️ 任何人可访问测试接口 |

## 四、可能后果

| 主体 | 可能后果 |
|---|---|
| **服务器** | 云厂商**强制关停实例 / 封禁公网 IP / 清退账号**（无需提前通知） |
| **域名** | 若已绑域名，域名可能被**列入黑名单**，影响后续正式备案 |
| **团队** | 影响**省级评审**材料与学校声誉；正式备案可能被**驳回或延长审核** |
| **个人** | 情节严重时，主管部门可依法处置（责令整改、罚款、追究责任） |

> 特别是：**「已发生的违规」会成为后续正式备案的负面记录**。
> 团队辛苦做的项目，不要因为一个端口配置翻车。

## 五、必须保持的现状（部署后自查）

每隔一段时间（或每次改动后）跑一遍：

```bash
# ① 确认没有 80/443 在监听
sudo ss -lntp | grep -E ':(80|443)\b'      # 期望：无输出

# ② 确认服务只在 8080
sudo ss -lntp | grep ':8080'               # 期望：有输出

# ③ 确认没有 Web 服务器在跑
systemctl is-active nginx apache2 httpd 2>/dev/null   # 期望：全部 inactive/unknown
dpkg -l | grep -E '^ii\s+(nginx|apache2)' 2>/dev/null # 期望：无输出

# ④ 确认没有证书申请工具
dpkg -l | grep -E '^ii\s+(certbot|acme)' 2>/dev/null  # 期望：无输出

# ⑤ 确认 MySQL 只绑回环
sudo ss -lntp | grep ':3306'               # 期望：只有 127.0.0.1:3306

# ⑥ 确认闸门开启
grep -c '^XJT_ACCESS_TOKEN=..*' /opt/xiaojietong/shared/server.env   # 期望：1

# ⑦ 确认无隧道类进程
ps -ef | grep -Ei 'frp|ngrok|cloudflared|autossh' | grep -v grep    # 期望：无输出
```

**一键式自查**可合并为上面 7 条的顺序执行；部署包内的
`scripts/10-status.sh` 已覆盖 ①②⑤⑥。

## 六、备案状态变化后的动作

| 阶段 | 动作 |
|---|---|
| **审核中（当前）** | 保持本方案现状；**不做任何对外动作** |
| **备案通过** | ① 确认备案号已下发；② 由负责人**单独立项**改造为正式上线方案（域名 + HTTPS + Nginx，见 `deploy/README.md`）；③ **不要**在本次联调环境上直接改端口或绑域名 |
| **备案被驳回** | 排查原因（材料/主体/域名）；**在通过前继续保持本方案现状** |
| **临时需要给外部演示** | **不要**开放公网；改用屏幕共享 / 局域网内网演示 |

## 七、给团队 4 人的三条要求

1. **不要把 `122.51.248.93:8080` 和访问令牌发到任何公开渠道**（群、朋友圈、GitHub、Issue）。
2. **发现有人在服务器上开了 80/443、装了 Web 服务器或隧道工具，立即制止并回滚**（见 §三）。
3. **每次上线代码前看一眼** §五 的自查命令；有异常就先回滚再排查。
