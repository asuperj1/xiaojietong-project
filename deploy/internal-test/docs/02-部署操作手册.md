# 02 · 部署操作手册

> 面向执行者，按顺序照做即可。全程使用 `http://122.51.248.93:8080`，
> **不涉及域名、不涉及 80/443、不涉及 SSL 证书**。

---

## 1. ⚠️ 第一步：云服务器【安全组】（控制台操作，脚本无法代做）

登录云控制台 → 该实例 → **安全组 / 防火墙** → 入方向规则，按下表配置：

| 方向 | 协议 | 端口 | 来源 | 动作 | 说明 |
|---|---|---|---|---|---|
| 入方向 | TCP | **8080** | **团队 4 人固定出口 IP**（多 IP 可用逗号分隔） | **允许** | 唯一业务入口 |
| 入方向 | TCP | **80** | 0.0.0.0/0 | **拒绝** | ⛔ 本阶段不对外提供网站服务 |
| 入方向 | TCP | **443** | 0.0.0.0/0 | **拒绝** | ⛔ 本阶段不使用 HTTPS |
| 入方向 | TCP | **3306** | 0.0.0.0/0 | **拒绝** | ⛔ 数据库严禁暴露公网 |
| 入方向 | TCP | **6379** | 0.0.0.0/0 | **拒绝** | ⛔ 缓存严禁暴露公网 |
| 入方向 | TCP | 22 | 你的办公/家庭 IP | 允许 | SSH 运维（勿对全网开放） |
| 出方向 | ALL | ALL | 0.0.0.0/0 | 允许 | 默认即可（拉 GitHub、装依赖） |

> **为什么必须限制 8080 来源？** 若对 `0.0.0.0/0` 开放，全网扫描器会在数小时内发现并尝试
> 探测接口（虽然有访问闸门兜底，但没有必要把门开着）。
> **不知道自己的出口 IP？** 在团队机器上访问 `https://api.ipify.org` 即得。

> ⚠️ **安全组与主机防火墙是两层独立防护**：安全组在云平台侧生效，`07-firewall.sh` 在系统内生效。
> **两层都要配**，任一层漏配都可能暴露。

## 2. 主机防火墙（脚本自动配置）

```bash
# 建议同时限制 8080 来源（把 TEAM_IPS 换成团队 4 人出口 IP，逗号分隔）
TEAM_IPS="1.2.3.4,5.6.7.8" sudo -E bash deploy/internal-test/scripts/07-firewall.sh

# 或先不限制来源（仅当安全组已限 IP 时）
sudo bash deploy/internal-test/scripts/07-firewall.sh
```

脚本行为（自动识别 `ufw` / `firewalld` / `iptables`）：

| 动作 | 内容 |
|---|---|
| ✅ 放行 | `22/tcp`（先放行，防止把自己锁在外面）、`8080/tcp`（或仅 `TEAM_IPS`） |
| ⛔ 拒绝 | **`80/tcp` `443/tcp` `3306/tcp` `6379/tcp`** |
| ✅ 默认 | 入方向 `deny`，出方向 `allow` |

**校验**：

```bash
sudo ufw status numbered          # 应看到 deny 80/443/3306/6379，allow 8080
sudo ss -lntp | grep -E ':(80|443|8080)\b'   # 只应有 8080
```

## 3. 逐步部署命令（首次）

```bash
# ---------- 0. 前置：需要 git / 已有 curl ----------
sudo apt-get update -y && sudo apt-get install -y git curl

# ---------- 1. 系统依赖（编译链 + Python + MySQL 服务端）----------
sudo bash deploy/internal-test/scripts/00-install-system-deps.sh
#   该脚本会顺带把 MySQL 的 bind-address 固定为 127.0.0.1（公网无法直连 3306）

# ---------- 2. 主机防火墙 ----------
TEAM_IPS="<团队出口IP列表>" sudo -E bash deploy/internal-test/scripts/07-firewall.sh

# ---------- 3. 一键部署（拉码 + venv + 编译 C++ + server.env + systemd）----------
export GITHUB_TOKEN=<只读 PAT>        # 私有仓库必需；公开仓库可省略
sudo -E bash deploy/internal-test/scripts/08-deploy.sh

# ---------- 4. 初始化数据库（首次执行一次；会二次确认）----------
sudo bash deploy/internal-test/scripts/05-init-database.sh '<MySQL root 密码>'
sudo bash deploy/internal-test/scripts/09-restart.sh

# ---------- 5. 体检 ----------
bash deploy/internal-test/scripts/10-status.sh
```

> **`GITHUB_TOKEN` 说明**：私有仓库需凭据。推荐在 GitHub 建 **只读 Deploy Key** 或
> **Fine-grained PAT（仅 Contents: Read）**。令牌只用于 clone，脚本不会写入磁盘。

## 4. 启动 / 停止 / 重启命令

```bash
# 启动
sudo systemctl start  xiaojietong-api

# 停止
sudo systemctl stop   xiaojietong-api

# 重启
sudo systemctl restart xiaojietong-api
#   或（带就绪检查，推荐）
sudo bash deploy/internal-test/scripts/09-restart.sh

# 开机自启（06 脚本已自动 enable）
sudo systemctl enable xiaojietong-api

# 状态
systemctl status xiaojietong-api
```

**systemd 单元关键行**（`/etc/systemd/system/xiaojietong-api.service`）：

```ini
WorkingDirectory=/opt/xiaojietong/app/backend
EnvironmentFile=/opt/xiaojietong/shared/server.env
ExecStart=/opt/xiaojietong/app/backend/.venv/bin/python -m uvicorn app.main:app \
    --host 0.0.0.0 --port 8080 --workers 1
Restart=always
```

> ⚠️ **`--workers 1` 不可改大**：限流计数、浏览量聚合、C++ 连接池都在进程内存里，
> 多 worker 会导致限流失真与重复计数（见 `01-部署方案.md` §8）。

**手工前台调试**（排查用，勿长期这样跑）：

```bash
cd /opt/xiaojietong/app/backend
set -a; . /opt/xiaojietong/shared/server.env; set +a
.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8080 --log-level debug
```

## 5. 访问方式

### 5.1 基地址与令牌

```bash
# 基地址
http://122.51.248.93:8080/api/v1

# 访问令牌（部署时 04 脚本生成，也在 /opt/xiaojietong/shared/server.env）
grep XJT_ACCESS_TOKEN /opt/xiaojietong/shared/server.env
```

### 5.2 调用示例

```bash
TOKEN=$(grep -oP '(?<=^XJT_ACCESS_TOKEN=).*' /opt/xiaojietong/shared/server.env)

# 健康检查（无需令牌）
curl http://122.51.248.93:8080/api/v1/health

# 业务接口（需令牌；再叠加业务登录态）
curl -H "X-Access-Token: $TOKEN" http://122.51.248.93:8080/api/v1/secondhand/items

# 未带令牌 → 403（闸门拦截，这是预期行为）
curl -i http://122.51.248.93:8080/api/v1/secondhand/items
```

### 5.3 小程序 / 前端联调

前端需把请求基地址指到本服务，并带上访问令牌：

- 微信开发者工具 → 详情 → 本地设置 → ☑ **不校验合法域名**（因为用的是 IP 而非域名）
- 请求封装中增加请求头 `X-Access-Token: <令牌>`
- **不要**把令牌硬编码进提交进仓库的文件（放本地私有配置）

> ⚠️ 真机调试时，手机需能访问该公网 IP；若手机连着 VPN/代理，请确认不拦截 `122.51.248.93`。

## 6. 日常更新

```bash
# 全量更新（拉最新代码 + 重编译 C++ + 重启）
sudo bash deploy/internal-test/scripts/08-deploy.sh

# 只改 Python（未动 C++ 层）→ 跳过编译，快很多
sudo bash deploy/internal-test/scripts/08-deploy.sh --no-build

# 只重启（改了 server.env 后）
sudo bash deploy/internal-test/scripts/09-restart.sh

# 换分支（例如联调某 feature 分支）
sudo bash deploy/internal-test/scripts/08-deploy.sh --branch feat/xxx
```

## 7. 注意事项（执行前必读）

| # | 事项 | 说明 |
|---|---|---|
| 1 | **不要改监听端口** | `scripts/lib/common.sh` 的 `assert_port_policy()` 会硬性阻止非 8080 |
| 2 | **不要绑域名 / 不要开 80·443** | 备案未完成，属违规（见 `04-ICP备案风险提示.md`） |
| 3 | **`XJT_ACCESS_TOKEN` 不得为空** | 为空则闸门关闭，任何人可访问测试接口 |
| 4 | **令牌只发给团队 4 人** | 不要发公开群、不要截图、不要提交进仓库 |
| 5 | **`server.env` 权限保持 600** | `04` 脚本已设置；不要 `chmod 644` |
| 6 | **改 `server.env` 后必须重启** | systemd `EnvironmentFile` 只在启动时读取 |
| 7 | **C++ 扩展必须本机编译** | `.so` 与 Python ABI 绑定，不可从开发机拷贝 |
| 8 | **不要在此环境跑生产数据** | 明文 HTTP；仅用于功能联调 |
| 9 | **首次编译约 2~5 分钟** | 2C4G 机器上 CMake+pybind11 较慢，属正常 |
| 10 | **MySQL 只绑 127.0.0.1** | 若被改成 `0.0.0.0`，请立即改回并重启 MySQL |

## 8. 首次部署验收（5 分钟）

```bash
# ① 服务在跑
systemctl is-active xiaojietong-api                 # → active

# ② 只监听 8080，无 80/443
sudo ss -lntp | grep -E ':(80|443|8080)\b'          # → 只有 8080

# ③ 闸门生效
curl -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/api/v1/secondhand/items
#   → 403（未带令牌，正确）

# ④ 闸门行为验证（12 项断言）
python3 tools/verify_access_gate.py \
    --base http://127.0.0.1:8080 \
    --token "$(grep -oP '(?<=^XJT_ACCESS_TOKEN=).*' /opt/xiaojietong/shared/server.env)"
#   → 12/12 通过

# ⑤ 从团队机器（外网）访问
curl -H "X-Access-Token: <令牌>" http://122.51.248.93:8080/api/v1/health
#   → {"status":"ok",...}
```
