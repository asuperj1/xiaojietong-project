## 2. 日志

```bash
# 实时跟随
journalctl -u xiaojietong-api -f

# 最近 100 行
journalctl -u xiaojietong-api -n 100 --no-pager

# 只看错误级别
journalctl -u xiaojietong-api -p err --no-pager

# 看闸门拒绝记录（排查是否被扫描 / 谁用错了令牌）
journalctl -u xiaojietong-api | grep '访问闸门拒绝'

# 按时间窗
journalctl -u xiaojietong-api --since '30 min ago' --no-pager
```

**启动成功的标志**（三个都要有）：

```
INFO:     ✅ 访问闸门已启用（豁免路径：/api/v1/health）      ← 或 "⚠️ 访问闸门未启用"
INFO:     ✅ jt_db 连接池已初始化 (127.0.0.1:3306/xiaojietong)
INFO:     Application startup complete.
```

## 3. 常见故障速查

| 症状 | 可能原因 | 排查 / 处理 |
|---|---|---|
| 服务起不来，日志 `ModuleNotFoundError: No module named 'celery'` | venv 依赖未装全 | `sudo bash scripts/03-setup-python-env.sh` 后重启 |
| 日志 `⚠️ jt_db C++ 扩展未编译` | `.so` 未编译或未拷到 `native/` | `sudo bash scripts/02-build-cpp.sh` |
| 日志 `ImportError: libmysqlclient.so.21` | 系统缺 MySQL 客户端库 | `sudo apt install -y libmysqlclient-dev` |
| 编译报 `未找到 MySQL C API (mysql.h)` | 缺 `libmysqlclient-dev` | 同上；再重跑 `02-build-cpp.sh` |
| 编译报 `Could NOT find Python` | 缺 `python3-dev` | `sudo apt install -y python3-dev` |
| `/api/v1/health` 返回 **404** | 请求了 `/health`（少前缀） | 正确路径是 **`/api/v1/health`** |
| 业务接口返回 **403** | 访问闸门拦截 | 加请求头 `X-Access-Token: <令牌>`（这是**预期行为**） |
| 带了令牌仍 403 | 令牌错 / 未重启 | 核对 `server.env` 的 `XJT_ACCESS_TOKEN`；`systemctl restart xiaojietong-api` |
| 业务接口返回 **2001 未登录** | 闸门已放行，是**业务层**要登录 | 这是正常的；需先调 `/auth/wechat-login` 拿业务 token |
| 从外网访问超时 | 安全组未放行 8080 / 来源 IP 不匹配 | 检查**云安全组**入方向 8080（注意来源 IP 限制） |
| 从外网 **Connection refused** | 主机防火墙拦了 / 服务没监听 0.0.0.0 | `sudo ss -lntp \| grep 8080`；`sudo ufw status` |
| 数据库连不上 | 密码错 / MySQL 未启动 / 端口不对 | `sudo systemctl status mysql`；核对 `server.env` 的 `XJT_DB_*` |
| 导出 `total` 数与实际不符 | 已知缺陷 `DATA-06` | 属业务缺陷，非部署问题（见审计报告） |
| SSE（`/chat/send`）不逐字输出 | 中间有代理缓冲 | 本方案**无 Nginx**，正常不会有此问题；若自行加了代理，需 `proxy_buffering off` |
| 返回 `500`，日志有 `NameError: err_server` | 已知缺陷（`secondhand.py`） | 属代码缺陷，非部署问题 |
| AI 接口返回降级/空结果 | 未安装 Ollama | 属**预期降级**（不影响其它接口）；需 AI 能力则安装 Ollama 并 `ollama pull` 模型 |
| 端口改不动 / 脚本报「端口策略违规」 | `assert_port_policy()` 拦截 | **这是设计如此**：本方案只允许 8080（见 `04-ICP备案风险提示.md`） |

## 4. 交付验收清单

> 逐项打勾。**任一项不通过，不要宣布"部署完成"。**

### 4.1 合规（最高优先级）

- [ ] 云安全组：**放行 8080**（来源限团队 IP）；**拒绝 80 / 443 / 3306 / 6379**
- [ ] 主机防火墙：`ufw status` 有 `deny 80` / `deny 443` / `allow 8080`
- [ ] `ss -lntp` **没有** 80 / 443 在监听
- [ ] **未安装** Nginx / Apache（`systemctl is-active nginx apache2` 均非 active）
- [ ] **未安装** certbot / acme.sh 等证书工具
- [ ] 服务器**未绑定任何域名**（无 A 记录指向本 IP）
- [ ] **无** frp / ngrok / cloudflared / autossh 类隧道进程
- [ ] MySQL 仅监听 `127.0.0.1:3306`
- [ ] 访问地址与令牌**未**发到任何公开渠道

### 4.2 服务

- [ ] `systemctl is-active xiaojietong-api` → `active`
- [ ] `systemctl is-enabled xiaojietong-api` → `enabled`（开机自启）
- [ ] 监听 `0.0.0.0:8080`
- [ ] 启动日志三条标志齐全（闸门 / 连接池 / startup complete）
- [ ] `--workers 1`（未被改成多 worker）

### 4.3 访问闸门

- [ ] 启动日志显示 `✅ 访问闸门已启用`
- [ ] 匿名访问业务接口 → **403**，且响应体为 `{"code":2003,...}`
- [ ] `tools/verify_access_gate.py --token <令牌>` → **12/12 通过**
- [ ] 关闭态自测 `tools/verify_access_gate.py`（不传令牌）→ **2/2 通过**（本机零回归）
- [ ] `/api/v1/health` 匿名可达（探活）；`/api/v1/health/detail` 匿名 **403**
- [ ] `server.env` 权限为 **600**

### 4.4 功能

- [ ] `curl http://122.51.248.93:8080/api/v1/health` → `{"status":"ok",...}`
- [ ] 带令牌访问 `/api/v1/secondhand/items` → `code=2001`（闸门已放行）
- [ ] 完成一次 mock 登录 → 拿到业务 token → 能查到业务数据
- [ ] 数据库表数 = **45**（`05-init-database.sh` 输出）
- [ ] `knowledge_doc` / `poi` / `campus_notice` 有种子数据
- [ ] `DATA-01` 回归：待审二手内容对他人不可见（`tools/verify_data01_audit_filter.py`）

### 4.5 团队可用性

- [ ] 4 人**都**已拿到：基地址 + 访问令牌 + 调用示例
- [ ] 4 人**都**能从自己机器成功访问 `/api/v1/health`
- [ ] 前端/小程序已配置基地址与 `X-Access-Token` 请求头

## 5. 回滚

| 场景 | 操作 |
|---|---|
| 新版本有问题 | `git -C /opt/xiaojietong/app log --oneline -10` 找到上一个好提交 → `git checkout <sha>` → 重跑 `08-deploy.sh --no-pull` |
| 配置写错（server.env） | 从备份恢复或重跑 `04-configure-env.sh`（已存在的密钥会保留）→ `09-restart.sh` |
| C++ 编译产物损坏 | `sudo bash scripts/02-build-cpp.sh` 重新编译 |
| 数据库被改坏 | 有备份则 `mysql xiaojietong < backup.sql`；无备份则重跑 `05-init-database.sh`（会**丢数据**） |
| 服务彻底起不来 | `sudo bash scripts/99-uninstall.sh` 清理后按 §3 重新部署 |

```bash
# 备份数据库（建议每次重大变更前执行）
mysqldump -h 127.0.0.1 -uroot -p --default-character-set=utf8mb4 \
    xiaojietong > /opt/xiaojietong/shared/backup-$(date +%Y%m%d%H%M).sql
```

## 6. 已知限制（部署相关）

| # | 限制 | 影响 |
|---|---|---|
| 1 | **部署 shell 脚本未在开发机做 `bash -n` 语法检查** | 开发机为 Windows，无 bash/WSL；首次执行若报语法错误，请把报错行贴到群里，立即修 |
| 2 | 脚本未在真实云服务器上完整跑过一轮 | 首次部署请**预留 30 分钟**并保持 SSH 会话；§3 故障表已覆盖常见问题 |
| 3 | 明文 HTTP | 不要在联调期传真实敏感数据 |
| 4 | 无自动备份 / 无监控告警 | 重大变更前手工 `mysqldump` |
| 5 | 单 worker | 不能靠加 worker 扩容（见 `01-部署方案.md` §8） |
| 6 | `XJT_ENV=dev`（非 prod） | `prod` 会因无微信凭据拒绝启动；安全由闸门 + 强随机 JWT 承担。**正式上线必须切 prod** |
